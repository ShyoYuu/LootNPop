# 멀티플레이 로비 검증 규약

> 상태: 기준 설계
> 마지막 갱신: 2026-10-15
> 소유 정보: 검증 시나리오, 실행 수단, 로그 판정, 모든 Phase 공통 스모크

## 1. 원칙

- 판정은 **패키지 빌드**(`LootNPop.exe`)로 한다. 에디터 `-game`은 `WITH_EDITOR` 경로를 타므로 대신할 수 없다.
- 메뉴 클릭 흐름은 사용자 플레이 테스트로 확인하고, 접속·초기화·대조는 로그로 판정한다. 화면 캡처로 판정하지 않는다.
- 플레이 테스트를 요청할 때는 한 번에 여러 시나리오를 묶어 1회 측정당 정보량을 늘린다.

## 3. 실행 수단

### 같은 PC 다중 인스턴스

- 패키지 exe를 여러 번 띄운다. PowerShell `Start-Process -FilePath ... -ArgumentList`를 쓴다(Git Bash `cmd //c start`는 따옴표가 깨져 사용자 화면에 오류 창을 띄운다).
- 메뉴 흐름 검증은 인자 없이 띄워 사용자가 조작한다. 주소는 `127.0.0.1`.
- 자동 판정이 필요한 접속 시나리오는 기존 명령줄 방식(호스트 `TestMap03?Listen`, 게스트 `127.0.0.1`)을 쓴다(L-007). 이 경로는 메뉴를 우회하므로 메뉴 자체는 검증하지 않는다.
- 메뉴 경로를 자동화해야 할 필요가 생기면(예: S-04·S-08 반복) 그때 명령줄 진입점을 추가한다. 미리 만들지 않는다.

### 다른 PC

- LAN 2 PC 1회 이상: 실제 NIC·방화벽 조건 확인(Windows 방화벽 허용 프롬프트, UDP 7777).
- 인터넷 테스트(Phase 1~4)는 포트포워딩 또는 VPN(Tailscale 등)으로 한다.

### 기존 하네스 회귀

- 로컬: `Saved/SliceOctant/NetworkV010/run-package-2p.ps1`(Normal·LateJoin 두 로그 대조). 커밋된 하네스: `Scripts/Profiling/RunPhase13Gate.ps1`.
- 쿡 맵 목록은 `-map=` 인자로 넘긴다(`Config`에 `MapsToCook` 없음). 새 맵(`L_Frontend`·`L_Lobby`)을 추가해야 한다.

## 4. 모든 Phase 공통 스모크

1. 패키지 빌드 성공(BuildCookRun 전에 에디터 타깃 빌드).
2. S-01·S-02·S-03·S-06을 패키지 같은 PC 2인스턴스로 통과.
3. 기존 명령줄 리슨 2P 하네스 Normal·LateJoin PASS.
4. 호스트·게스트 로그에 assert·ensure·fatal 0, 새 Error 0(기존 ShaderMap·CharacterMovementComponent 추출 오류는 기준선).

## 5. 로그 판정

- 위치: 패키지 출력 `.../Windows/LootNPop/Saved/Logs/`. 같은 PC 다중 인스턴스는 호스트 `LootNPop.log`, 게스트 `LootNPop_2.log`…(실행 순서에 따라 번호가 붙는다).
- 확인 표식: `ALNPGameMode: Server init complete`, `LNPGameState: Server phase changed`, 게스트 Ready·스폰, Mass warm-up 로그 `Mass entity template warm-up starting. NetMode=N`(호스트는 `NM_ListenServer`인 2여야 한다, L-002).
- 실패 복귀 경로는 GameInstance가 남기는 실패 종류·사유 로그로 판정한다(Phase 1에서 추가).
