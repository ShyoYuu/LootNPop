# 온라인 백엔드 비교 — IP 직접 접속·LAN·Steam·EOS

> 상태: 검증 필요(Phase 5 착수 시 재조사)
> 마지막 갱신: 2026-10-15
> 소유 정보: 백엔드 선택 근거, L-001의 이유, Phase 4·5 착수 시 확인할 질문

## 1. 결론

**IP 직접 접속을 먼저 구현하고, Steam·EOS는 마지막 Phase(5)에서 고른다(L-001).** 처음부터 고려할 것은 백엔드 자체가 아니라 교체 지점의 경계다 — 메뉴·대기실이 GameInstance의 접속 진입점 하나로만 접속하게 만들어 두면 된다(`design/Architecture.md` §1).

이유:

1. **테스트에 어차피 필요하다.** Steam은 PC 한 대에 계정 하나가 로그인되므로 같은 PC에서 호스트·게스트 두 인스턴스를 서로 다른 사용자로 띄우기 어렵다. EOS도 여러 계정 로그인용 개발 도구 준비가 든다. IP 직접 접속은 아무 준비 없이 같은 PC 다중 인스턴스가 된다. 그래서 백엔드를 붙인 뒤에도 개발·LAN 경로로 남긴다.
2. **지금 실제 위험은 백엔드와 무관하다.** "메뉴 → listen 맵 열기 → 접속 → 4단계 초기화 → 중간 참가 → 실패 복귀"가 패키지에서 도는지가 먼저다. 이 프로젝트는 맵 로드 시점 NetMode에 의존하고(L-002) seamless travel이 맞지 않는다(L-003). 어느 백엔드를 쓰든 이 흐름은 같다.
3. **백엔드가 바꾸는 범위는 좁다.** ① 접속 주소를 얻는 방법(직접 입력 ↔ 세션 검색·친구 초대)과 ② NetDriver(NAT 릴레이)뿐이다. 메뉴·대기실·GameMode·초기화 흐름은 재사용된다.
4. **결정을 늦출수록 정보가 많다.** 배포 목표가 아직 정해지지 않았고(2026-10-15 사용자 답변), 백엔드 선택은 배포 채널에 묶인다.

## 2. 비교

| 항목 | IP 직접 접속 | LAN 세션(Null) | Steam | EOS |
|:---|:---|:---|:---|:---|
| 방 찾기 | IP 직접 입력 | LAN 브로드캐스트 검색 | 로비·친구 초대(오버레이) | 로비·세션 검색, 초대 |
| NAT·인터넷 | 호스트 포트포워딩(UDP 7777) 또는 VPN 필요 | LAN 한정 | 릴레이(SteamSockets)로 해결 | P2P 릴레이로 해결 |
| 같은 PC 다중 인스턴스 테스트 | 바로 가능 | 바로 가능 | 어렵다(PC당 로그인 계정 1개) | 개발용 인증 도구로 가능, 준비 필요 |
| 외부 준비 | 없음 | 없음 | Steamworks 파트너 등록·App ID(개발 중에는 공용 테스트 App ID 사용 가능), Steam 클라이언트 실행 | Epic 개발자 포털 제품·샌드박스·자격 증명, 플레이어 식별 방식 결정 |
| 배포 채널 제약 | 없음 | 없음 | 사실상 Steam 배포 전제 | 채널 무관(Steam 배포와도 병행 가능) |
| 이 프로젝트의 미검증 위험 | 없음(현재 경로) | 적음 | SteamSockets NetDriver + Iris·MassReplication | EOS NetDriver + Iris·MassReplication |

표의 외부 준비·정책 항목은 일반 지식 기준이다. Phase 5 착수 때 최신 문서로 다시 확인한다.

## 3. IP 직접 접속의 한계와 대응

- 인터넷 너머 친구와 하려면 호스트가 공유기 포트포워딩을 하거나, 양쪽이 같은 VPN(Tailscale·ZeroTier 등)에 들어가야 한다. 지인 테스트는 VPN으로 충분하다.
- 방 목록이 없다 — Phase 4의 LAN 세션이 LAN 안에서는 이를 메운다.
- 호스트 IP가 노출된다. 지인 테스트 단계에서는 수용한다.

## 4. 착수 시 확인할 질문

### Phase 4(세션 계층)

- UE 5.8에서 세션 API로 OnlineSubsystem(v1), Online Services(v2), CommonUser 플러그인 중 무엇을 쓸지. Steam·EOS 양쪽 구현이 갖춰진 쪽을 고른다.
- Null 백엔드 LAN 검색이 Iris 리슨 서버와 함께 패키지에서 동작하는지.
- 세션 속성(방 이름·인원·진행 중)을 대기실·게임 맵 전환 사이에서 누가 갱신하는지.

### Phase 5(온라인 백엔드)

- 배포 목표가 정해졌는가 — Steam 출시면 Steam, 채널 무관·크로스 스토어면 EOS, 미정이면 보류(IP·LAN 유지)도 선택지다.
- 선택한 백엔드의 NetDriver에서 Iris 복제·MassReplication 버블·Iris 델타 압축 설정(`LNPMassClientBubbleInfo`)이 그대로 동작하는가. 첫 단위 스파이크로 패키지 리슨 2P·중간 참가를 확인한다.
- 릴레이 경유 시 대역폭 상한(클라이언트당 150KB/s)·지연이 전투 판정(Lag Compensation)에 주는 영향.
- 같은 PC 다중 인스턴스 테스트 방법(개발용 인증 도구, 계정 여러 개).
- 데디서버 지원: 플레이어 계정 없이 서버가 로그인·세션 광고를 할 수 있는지, 리슨 방과 같은 검색 목록에 섞을 수 있는지(L-008 ③). 데디서버 자체는 별도 작업이지만 백엔드 선택이 이를 막지 않아야 한다.
