# 인게임 메뉴 기획서

## 1. 목표와 원칙

- CommonUI 모듈로 **게임패드 우선** 조작이 성립하는 인게임 메뉴를 만든다. 마우스는 보조 수단이다.
- 모든 조작 설명은 **PlayStation 게임패드**(듀얼쇼크/듀얼센스) 기준으로 기술한다.
- MVVM을 쓸 수 있는 곳은 MVVM을 쓴다. 단 리스트/타일 데이터는 바인딩할 수 없다 — [TechDesign_HUD.md](TechDesign_HUD.md) §8의 제약.
- 화면 중앙 **팝업**으로 크게 띄우되 전체 화면을 완전히 가리지 않는다.
- 모든 UI 요소는 **반투명**이다. 메뉴를 보는 중에도 긴급 상황(피격·적 접근)을 눈치챌 수 있어야 한다.

---

## 2. 열기 / 닫기 / 일시정지

| 입력 | 동작 |
|:---|:---|
| 터치패드 버튼 (→ `Gamepad_Special_Left`) / 키보드 `I` | 마지막으로 보던 탭으로 진입. **다시 누르면 닫힘** |
| 옵션 버튼 (`Gamepad_Special_Right`) / 키보드 `O` | **항상 환경설정 탭**으로 진입. **다시 누르면 닫힘** |
| ○ 버튼 (`Gamepad_FaceButton_Right`) / 키보드 `Esc` | 메뉴 닫기 (포커스가 하위 패널에 있으면 먼저 상위로 복귀) |

**키보드 개발 편의 매핑** — 게임패드 없이도 전부 조작할 수 있게 보조 키를 둔다.
탭 이동 `Q`/`E`, 선택 `Enter`·`Space`, 뒤로 `Esc`, Grid 셀 이동 `←↑→↓`·`WASD`.

> ⚠️ **화살표는 방향 이동 전용으로 비워 둔다.** UI 액션(탭 이동·선택·뒤로)에 배정하면
> 액션이 방향키를 먼저 소비해 인벤토리 Grid의 셀 이동이 불가능해진다.
> 왼손이 WASD에 놓인 상태에서 `Q`/`E`(탭)·`Space`(선택)·`Esc`(뒤로)로 전부 닿는 배치다.

> ⚠️ 기획 원안의 "터치패드 버튼"은 Windows의 XInput/Raw Input 경로에서 UE에 키 이벤트가 전달되지 않는다.
> 물리 버튼 위치가 가장 가까운 `Gamepad_Special_Left`(Share/Create 버튼)로 대체한다.
> DualSense 전용 입력 플러그인을 도입하면 실제 터치패드 버튼으로 교체할 수 있다.

### 마지막 탭 기억 규칙

- 캐릭터 스탯 탭과 인벤토리 탭 중 **닫기 직전에 보던 탭**으로 진입한다.
- 첫 진입이거나 마지막으로 보던 탭이 환경설정이었다면 → **캐릭터 스탯 탭**.
- 즉 환경설정 탭은 기억 대상이 아니다. 옵션 버튼으로만 직행한다.

### 일시정지

- 스탠드얼론일 때만 메뉴를 열면 게임을 일시정지한다. **멀티플레이에서는 일시정지하지 않는다.**
- 멀티에서는 메뉴를 보는 동안에도 피격될 수 있다 — 반투명 설계가 이를 보완한다.

### 게임플레이 입력 차단

- 메뉴가 열려 있는 동안 폰의 입력 매핑 컨텍스트를 제거해 이동·시점·공격·상호작용을 **전면 차단**하고, 닫을 때 복원한다.
- 이유: 게임패드 좌스틱이 Grid 커서 이동과 캐릭터 이동을 동시에 일으키는 충돌을 원천 차단한다.

## 3. 레이아웃

```
┌─────────────────────────────────────────────────────┐
│  ┌──────────┬──────────┬──────────┐                 │  ← 상단 탭 팝업
│  │ 캐릭터   │ 인벤토리 │ 환경설정 │   L1 ◄  ► R1    │    (현재 탭은 스케일 확대)
│  └──────────┴──────────┴──────────┘                 │
│                                                     │  ← 빈 공간 (두 팝업이 분리되어 보이게)
│  ┌───────────────────────────────────────────────┐  │
│  │                                               │  │  ← 하단 메인 팝업
│  │              (탭 컨텐츠 영역)                 │  │
│  │                                               │  │
│  └───────────────────────────────────────────────┘  │
│                                                     │
│              [○ 닫기] [✕ 선택] [L1/R1 탭]           │  ← 하단 액션 바
└─────────────────────────────────────────────────────┘
```

- 상단 탭 바와 하단 메인 패널 사이에 **의도적인 빈 공간**을 둔다. 하나의 창이 아니라 **두 개의 팝업**이 동시에 떠 있는 느낌을 준다.
- 상단 탭에서 **현재 출력 중인 카테고리는 스케일을 살짝 확대**해 강조한다(선택 밑줄과 병행).
- 배경은 `BackgroundBlur` + 반투명 어두운 오버레이. 게임 화면이 흐릿하게 비쳐 보인다.
- 하단 액션 바는 현재 포커스에서 가능한 조작을 키 심볼 + 라벨로 표시하며, **키보드/게임패드 전환 시 심볼이 자동으로 바뀐다**.

> ⚠️ 키 심볼은 아이콘 이미지가 아니라 **텍스트**다. 프로젝트에 키 글리프 텍스처가 없어
> (`UCommonInputBaseControllerData` 에셋 0개) `○ × □ △ L1 R1 L3` / `ESC SPACE ENTER Q E F` 같은 문자로 그린다.
> 아이콘 아트가 준비되면 교체 가능하다 — [TechDesign_InGameMenu.md](TechDesign_InGameMenu.md) §3.4 참조.

---

## 4. 탭 이동

- `L1` / `R1`으로 좌우 카테고리 이동. 양 끝에서의 순환 여부는 CommonUI 기본 동작(순환)을 따른다.
- 카테고리는 **캐릭터 스탯 / 인벤토리 / 환경설정** 3종. 추후 추가가 가능한 구조로 만든다.

## 5. 캐릭터 스탯 탭

세 영역이 위에서 아래로 배치된다.

### 5-1. 스탯 리드아웃

캐릭터 AttributeSet의 스탯을 `최종값 (합연산결과 × 곱연산배율)` 포맷으로 출력한다.

```
최종값    (합연산결과 × 곱연산배율)
 흰색       회색        초록
```

예시 (라벨은 고정 폭 열, 배율 스탯은 퍼센트 표기):

```
HP             100 / 150
Max HP         150 (150 × 100%)
Attack         36.0 (30.0 × 120%)
Attack Speed   130% (100% × 130%)
Defense        50.0 (50.0 × 100%)
Move Speed     130% (130% × 100%)
Loot Speed     200% (100% × 200%)
Poise Resist   10.0 (10.0 × 100%)
```

**표시 행은 8행이다** — HP(현재/최대) + 스탯 7종. HP 행만 현재/최대 쌍이라 합·곱 분해를 쓰지 않고,
최대 체력의 분해는 `Max HP` 행이 담당한다. 행 목록과 표기 방식은 코드의 스탯 메타 테이블 하나가 정하므로
스탯을 추가하면 리드아웃 행도 따라 늘어난다.

**공격력에 곱연산 스탯을 따로 두지 않는다.** 곱연산은 별도 어트리뷰트가 아니라 같은 어트리뷰트에 걸리는
버프 채널이므로, "공격력" 한 행의 **배율 항(B)** 으로 나타난다. 데미지 공식도
`(기초 공격력 + 무기 보너스) × 배율`로 같은 관계다.

#### 색상 의미

- **합연산 버프**는 장비·영구 적용으로만 들어오므로 버프량으로 따로 보이지 않고 **기본 스탯에 합산된 것처럼** 회색으로 표기한다.
- **곱연산 버프**만 초록색 배율로 보인다. 곱연산은 합연산이 모두 적용된 뒤에 곱해진다.
- 기획 원안의 "검은색"은 어두운 반투명 배경에서 보이지 않으므로 **흰색**(기본 텍스트 색)으로 대체한다.
- 곱연산 버프가 없어도 괄호 표기를 유지한다 (`(30.0 × 100%)`).

> ⚠️ 이 표기는 향후 버프 시스템 개선(모든 스탯에 합/곱 버프 도입)을 전제로 미리 깔아둔 기반이다.
> 현재 콘텐츠에는 합연산 버프가 대부분이라 배율은 대개 100%로 표시된다.

### 5-2. 장착 장비

- 현재 장착 중인 **무기 슬롯 1칸**의 아이콘만 표시한다. 비어 있으면 플레이스홀더.
- 스킬 슬롯은 이번 범위에서 제외한다 (스킬 장착 UI가 아직 없음).

### 5-3. 적용 중인 버프

- 적용 중인 버프의 **아이콘 + 남은 시간**을 가로로 나열한다. 남은 시간은 1초 주기로 갱신된다.
- 지속시간이 무한인 버프는 시간 표기를 생략한다.

## 6. 인벤토리 탭

좌우 2분할. 좌측 Grid, 우측 디테일.

```
┌──────────────────────────┬─────────────────────┐
│ ┌──┐┌──┐┌──┐┌──┐┌──┐     │  ┌────┐             │
│ │  ││  ││  ││  ││  │     │  │아이│  아이템 이름 │
│ └──┘└E─┘└──┘└──┘└──┘     │  │ 콘 │             │
│ ┌──┐┌──┐┌──┐             │  └────┘             │
│ │  ││  ││  │             │  스탯 / 레벨        │
│ └──┘└12┘└──┘             │                     │
│                          │ [Equip][Merge][Drop]│
└──────────────────────────┴─────────────────────┘
    ✕ → 디테일로              ○ → Grid로
```

### 6-1. 좌측 Grid 패널

- 보유 중인 **무기·버프·기타 아이템을 모두** 직사각형 아이콘 셀로 표현한다.
- 열 수는 고정, 아이템 개수만큼 셀이 동적으로 생성되고 세로 스크롤된다.
- **방향키 / L3 스틱**으로 셀 간 이동. 선택된 셀은 하이라이트된다.
- 배지는 **셀의 세 모서리**로 나눈다 — 좌상단 장착 표시, 우상단 버프 잔여 초(1초 갱신), 우하단 무기 레벨.
  한 칸에 몰아넣으면 레벨과 잔여 시간이 서로를 가린다.
- **장착 중인 무기도 Grid에 표시된다.** 기존 인벤토리 패널은 장착본을 숨겼으나,
  본 기획이 "장착 여부 표시"를 요구하므로 노출로 변경한다.
- `✕` 버튼으로 포커스를 **Grid → 디테일 패널**로 이동한다.

### 6-2. 우측 디테일 패널

- 선택된 아이템의 상세: 큰 아이콘, 이름, 스탯 변경 목록, 그리고 무기는 `Lv. 현재/최대`·버프는 잔여 시간.
- 버튼 3종이 이곳에 위치한다.
  - **Equip**: 무기에만 표시. 이미 장착 중이면 비활성 + "Equipped" 표기.
    무기 슬롯이 1개라 다른 무기를 장착하면 자동 교체되므로 별도 Unequip 버튼은 두지 않는다.
  - **Merge**: 무기에만 표시. 같은 종류·같은 레벨의 재료를 모아 레벨을 올린다. 재료 수가 라벨에 함께 나오고
    (`Merge (보유/필요)`), 부족하면 비활성, 최대 레벨이면 `Max Lv.`로 바뀐다.
  - **Drop**: 장착 중이 아닌 아이템에만 활성. 버프도 드랍 가능하며 잔여 시간을 유지한 채 LootDice로 스폰된다.
- 포커스가 디테일 패널에 있을 때 `○`는 **디테일 → Grid** 복귀다. 메뉴 닫기로 이어지지 않는다.
- Grid가 비어 있으면 디테일 패널은 "아이템 없음" 안내를 표시한다.

## 7. 환경설정 탭

- 현 범위에서는 **빈 패널 + "준비 중" 안내 문구**만 배치한다.
- 탭 자체는 정상 동작하며(진입/이탈/액션 바), 내용만 추후 채운다.

---

## 8. 조작 요약

하단 액션 바에 표시될 항목이기도 하다.

| 버튼 | 캐릭터 스탯 / 환경설정 | 인벤토리 Grid | 인벤토리 디테일 |
|:---|:---|:---|:---|
| `○` / `ESC` | 메뉴 닫기 — `Close` | 메뉴 닫기 — `Close` | Grid로 복귀 — `Back` |
| `✕` / `ENTER` | — | 디테일로 이동 — `Details` | 버튼 실행 — `Confirm` |
| `L3` / `WASD` | — | 셀 이동 — `Move` | 버튼 이동 — `Move` |
| `L1`·`R1` / `Q`·`E` | 탭 이동 — `Tab` | 탭 이동 — `Tab` | 탭 이동 — `Tab` |

라벨 원본은 영문이다(위 표의 코드체). Grid가 비어 있으면 가리킬 대상이 없는 `Details`·`Move` 두 칸은 빠진다.

> ⚠️ **`✕`와 방향 이동은 CommonUI 입력 액션이 아니다.** Slate 네비게이션이 포커스된 위젯을 직접 처리하는
> 경로라 액션 라우터에 바인딩이 없다. 그래서 엔진 기본 `UCommonBoundActionBar`로는 이 두 행을 그릴 수 없고,
> 힌트 목록을 직접 공급하는 커스텀 바를 쓴다.
