# Acropolis_00 V016 — 외곽 구덩이 탈출 훅

2026-10-13. 사용자가 V015의 경계 복귀로 모두에서 점프·훅 없이 경계에 도달한다고 확인했다. 다만 `WhereAmI`로 신고한 외곽 구덩이 한 곳에 탈출 수단이 없어, 위쪽의 평탄한 지면에 훅 하나를 추가했다. 지형 원본은 승인된 `Acropolis_00_V015.blend`를 유지하고 장치 배치만 V016으로 갱신한다.

## 변경과 재현

- 신고: slot 5, local `X=-13056 Y=-24388 H=-2107`, 발밑 `SM_Octant_Acropolis_00_R30000`. 경사로 측면에 약 22m 깊이로 남은 좁은 공간이다.
- 새 마커: `Anchor_PitRecovery_01`, local `[-13000,-22000,4000]`, 사거리 7000cm. 구덩이 안에서 가장자리와 몸체가 충돌하지 않도록 높이를 확보했고, 상단 평탄한 지면 안쪽으로 당겨지게 했다. 런타임 장치는 기존과 같은 `BP_GrappleAnchor`를 사용한다.
- 검토점: `AcropolisPitRecovery`. 신고 위치에 다시 내려서 훅을 조준하고, 상단 지면에 착지하는 동작만 확인하면 된다.
- 지형 메시 63개의 파일 SHA256, 기존 훅 28개의 자세·사거리, 훅/Pod 마커 ID 61개를 보존했다. 현재 훅 29개, Pod 33개, 게임플레이 마커 62개다.
- 배치 원본은 `Art/Octants/Acropolis_00/pit-recovery.json`과 갱신된 `placement.json`, 반영 스크립트는 `Scripts/RepairAcropolisPit.py`다. 전체 재조립 시 V015 지형 반입·경계 보정·검토점 갱신 뒤 이 스크립트를 실행하고 베이크한다. 기존 마커는 재발급하지 않는다.
- 수정 전 복구본은 `Saved/SliceOctant/Acropolis_00/V016/Before/`에 보존했다. 진단 렌더는 같은 버전의 `PitBefore.png`다.

## 검증

구덩이 하부의 250cm 좌표 간격 표본 중 H<-2000인 45곳에서 새 훅까지 시야 광선과 반경 100cm 구 sweep이 통과했다. sweep 시작은 표면 위 150cm이며, 실제 Mover의 이륙·카메라 조준 검사를 대신하지 않는다. 최대 거리는 6327.20cm로 사거리 7000cm 안이다. 훅 아래 착지면의 로컬 X/Y ±500cm 영역 9곳은 지면 높이가 0에 가깝고 평탄하다. 승인된 지형을 바꾸지 않아 옥탄트 경계 규약도 유지된다.

저장본 검사는 마커 자세 62개, 기존 Pod 바닥·동굴·훅 시야, Pocket_05 틈 201광선, 경계 복귀로 2286광선, 베이크 seam 표본 2208개와 새 훅의 45개 이동 공간을 확인한다. 베이크는 기존 DA 경로에 갱신하며 실제 풀과 전역 설정은 수정하지 않는다. 보고서는 `Art/Octants/Acropolis_00/`와 `Saved/SliceOctant/Acropolis_00/V016/`에 둔다. V015 지형 보고서는 변경 없는 기준 증거로 유지한다.

최종 저장본 검사와 재베이크가 통과했다. 경계·스폰 구성·저장 베이크 현재성의 네이티브 자동 검사 3개도 오류 0·경고 0으로 통과했다. 실제 풀의 SHA256은 수정 전과 동일하다. 인계 시 `TestMap03`을 열고 PIE는 시작하지 않는다.

사용자 PIE에서 아래 명령으로 신고 지점에 이동한다. **훅 조준 → 사용 → 상단 지면 착지 → 걷기 복귀**가 통과 조건이다. 기존 경사로 전체를 다시 탐색할 필요는 없다.

```text
LNP.Debug.TeleportToReview AcropolisPitRecovery
```

2026-10-13 사용자 PIE 확인 완료: 새 훅이 정상적으로 보이고, 구덩이에 빠진 뒤에도 훅으로 원활하게 탈출할 수 있음을 확인했다. 기존 구성·부유섬/동굴 개선·틈 수정·9개 경계 복귀로에 이어 마지막 신고 지점도 해결됐으므로 **Acropolis_00의 지형·이동 동선 프로토타입을 확정**한다. 기준은 지형 V015 + 장치 배치 V016이다.
