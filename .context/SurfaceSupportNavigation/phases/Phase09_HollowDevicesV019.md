# Hollow 훅 역할 정리·Shuttle 절벽 연결 V019

2026-10-10. V018 사용자 PIE에서 **패널 크기는 채택**, 협곡 훅의 정돈/잔도 착지는 실패했다. Shuttle 섬 위치에 맞춰 마주 보는 절벽 정상과 패널을 연결하고, 장거리 판의 중력 수평 회전을 추가한다. V017 승인 외피·V018 섬 위치/크기와 두 판의1200×1200×30cm는 유지한다.

**후속 사용자 PIE: 호스트·게스트 패널 왕복과 회전 채택. 훅 정돈은 개선됐지만 일부 잔도의 관성 착지는 실패했으며, 정상 도착·외곽 복귀 추가 요청은 [V020](Phase09_HollowDevicesV020.md)에서 진행한다.** V019 생성 lint0/베이크·정식2개 검사(3.621초/오류0/경고0), 원본/Live Coding/8slot 회전 검사는 통과했다. PIE 장치 로그의 `authoredRegion=146`과 사용자 피드백을 추가 시드 훅 제외 근거로 남긴다. 전역 anchors38/50을 Hollow 수량으로 해석하지 않는다. 복구는 `Saved/SliceOctant/Hollow_00/DevicesV019/Before`다.

## 훅 역할과 착지 계약

V018 검사는 이전 발판→앵커 시야/사거리만 확인했으며 앵커 바로 아래의 착지를 놓쳤다. 또한 전역 시드 훅이 수동 마커와 섞였다. 직전 PIE의 전역 배치는46/50이며 이를 Hollow 내부 수량으로 해석하지 않는다.

- 협곡 내부는 **잔도9개 각각1개 + 양쪽 정상2개 + 중앙 수직 탈출1개 =12개**. 서쪽 Low→PocketLip→Mid→High→Top, Mid→Panel 분기. 동쪽 Low→Panel→Mid→High→Top이다.
- 밖의 역할7개는 Ascent/Arena/Shuttle/BackPocketLip/NorthShaftLower/NorthShaftUpper/Rim. 북쪽 좁은 축의 중간 판을 거치는2단계는 중앙 협곡 축과 별개다. 전체 수동 훅26→19개, 임의 인덱스 대신 `Anchor_WestLow`처럼 역할을 이름에 기록한다.
- EastSaddle, 중앙 축 아래 중복 훅, 옛 Dock 복귀 훅, 공동 Pod 전용2개, 비밀길 굽이2개를 제거한다. 중앙 `BasinExit`는 공동의 중앙 축 바닥에서 직접 보이며, `WestTop`은 Shuttle 복귀도 맡는다.
- 수직 축용3개를 제외한16개는 앵커에서 구체 중심 반대 방향으로 쏜 첫 광선이 지정한 잔도/섬에 도달해야 한다. 바닥 오차10cm 이내, 낙하 캡슐42/96cm 통과, 착지점 주변±60cm 네 방향 바닥을 검사한다. 상위 발판 밑면을 피하려고 착지면 밖으로 밀어내지 않는다.
- Hollow 마커에 `LNP.Grapple.AuthoredOnly`를 붙인다. 월드 장치 배치기는 해당 마커의 스트리밍 레벨에서 추가 시드 훅을 제외한다. 다른 레벨의 훅과 런처 정책은 유지한다. 배치 로그에 `authoredRegion` 기각 수를 남긴다. 실제 PIE에서 제외 여부는 다시 확인해야 한다.

## Shuttle와 패널 회전

사용자 월드 좌표는 slot7이다. 섬의 발밑은 local약(−8750,−12390,H6100), 마주 보는 절벽은(−8648,−6868,H6099)이며 **서쪽 절벽 H6000**이다. Pawn 높이가 포함된 좌표를 그대로 접안 바닥으로 쓰지 않는다.

- Shuttle 섬은(−9000,−14500,H6000) 유지. 새 패널은(−8700,−7350,H6015)↔(−9000,−12000,H6015), 직선32.37m/600cm/s/양 끝3초 정차. `HollowShuttleDock` 검토점은 서쪽 절벽(−8700,−6600,H6000)으로 옮긴다. 옛 Dock 외피는 승인 형상이라 유지한다.
- 협곡 횡단 패널은(3000,±1300,H2015)/400cm/s/3초, 직선24.11m. 두 판의 폭과 두께는 사용자 채택값을 유지한다.
- 열린 왕복 경로는 출발/도착 위치의 `Up=-Position.Normalized()`에 수평 정렬한다. 출발 방위를 유지하며 두 자세의 quaternion을 **거리 비율로 Slerp**한다. 닫힌 루프는 기존 고정 자세다. 원본 경로·시작 서버 시각으로 매번 계산하므로 누적 적분이나 새 복제 필드는 없다.
- 정차 시 각속도0, 복귀 시 반대 각속도. kinematic body에 각속도를 넣고 DynamicSupport snapshot에도 게시한다. 가장자리 이탈 속도는 `v + omega cross r`이다. Mover base 추종의 틱 순서와 NPC 이동 알고리즘은 바꾸지 않는다.

## 마지막 PIE 묶음 — 정식 검사 통과 후

1. `HollowBasin`에서 양쪽 잔도 체인과 정상까지 이동한다. 각 훅 아래 해당 잔도에 착지하고 다음 훅을 고르기 쉬운지, 불필요한 훅이 남았는지 확인한다. 중앙 공동은 `BasinExit` 하나로 탈출한다.
2. 새 `HollowShuttleDock`↔`HollowShuttleIsland` 패널 왕복. 출발/도착 수평·중간 회전, 중앙/가장자리 탑승 유지와 양방향 접안을 확인한다. 섬→공용 WestTop 훅 복귀도 확인한다.
3. 횡단 패널도 양방향 탑승/접안을 확인한다. 가능한 기존 멀티 PIE 설정에서는 호스트/게스트의 같은 패널 자세·탑승도 확인한다. 새 네트워크 시험 환경을 별도로 구축하지 않는다.

실패는 현재 Hollow slot을 다시 확인하고 `LNP.Debug.WhereAmI`와 이동 방향을 기록한다. 외피 확정과 장치 조정 완료는 구분한다.
