# Phase 12 — 투사체 판정 정확성과 성능 최적화

> 상태: 진행 중
> 착수: 2026-10-04

## 범위와 진행 규칙

캐시 도입 검토와 별개로 `ProjectileHitDetection`의 대상 수집·후보 제외·되감기·캡슐 판정·월드 query 비용을 줄인다. 먼저 정확한 캡슐 판정을 확보하고 내부 비용을 분해한다. 구현 단위마다 검증 결과를 보고하고 사용자에게 계속 진행할지 확인한다.

에디터 상태로 방법의 우선순위를 정하지 않는다. MCP가 효율적이면 연결을 요청하고, 전체 빌드가 필요하면 실행 중인 에디터의 저장·종료를 요청한다.

## 구현 단위

1. `SegmentHitsCapsule` 정확성 수정: 투사체 선분과 캡슐 축 선분의 최소 거리 제곱을 비교한다. 원래 캡슐 반지름과 추가 판정 반경을 분리하고, 축은 `HalfHeight - CapsuleRadius`로 구성한다. 제곱근·정규화 없이 점·평행·끝점 제한을 처리한다. 명시적 회귀 사례와 엔진 기준 함수 대조, 관련 월드 충돌 자동화 및 전체 빌드로 검증한다.
2. 내부 비용 계측과 정확성 수정본 기준선: 최신 Phase 13과 동일 조건에서 수집·제외·되감기·판정·월드 query 비용을 분해한다. 개별 타겟마다 trace를 찍지 않고 선택된 투사체만 순환 샘플링해 계측 비용을 제한한다. 상세 계측을 끈 trace 없는 반복으로 성능 기준선을 판정한다.
3. 후보 축소와 계산 순서 최적화: sphere 선행 검사, 공간 질의, 되감기 순서·재사용을 비교한다. 현재 위치만으로 되감기 대상 후보를 제외하지 않는다. 보수적 경계와 기존 판정 결과 대조로 누락을 검증한다. 실측 이득이 있는 방법만 채택한다. 변경 크기에 따라 단위를 나누어 진행 확인을 받는다.
4. 월드 query·캐시 검토 및 통합 검증: 계측 근거가 있을 때만 horizon 등 별도 최적화를 검토한다. 정확성·네트워크·패키지 리슨 2P 및 trace 없는 반복 성능을 확인한다.

## 공간 필터의 기존 구조 검토 (단위 3b 후보)

`Enemy/LNPEnemySpatialGrid.h/.cpp`의 `ULNPEnemySpatialGridSubsystem`과 `ULNPFlyingSpatialGridSubsystem`이 최근 도입된 등장방형 축소 행 그리드다. 카운팅 정렬 2패스·셀별 연속 후보 저장은 재사용할 수 있다. 다만 기존 subsystem의 현재 데이터와 `ForEachNeighbor`를 투사체에 바로 연결하지 않는다.

- 서버 이동 전 재구축하며 죽어가는 적을 제외한다. 투사체는 서버/클라이언트의 판정 시점 캡슐 전체를 수집하므로 별도 소유 데이터 또는 시점·집합 보완이 필요하다.
- 현재 각반경 `Radius / Distance`와 행 중심 기반 경도 범위는 근사다. 투사체의 보수적 후보 조회에는 정확한 구면 경계·극·경도 이음매·원점/긴 선분 전수 fallback 검증이 필요하다.
- 되감기는 과거 선형 위치뿐 아니라 배회 경로도 평가한다. 현재 위치만 색인해 과거 피격을 제외하지 않는다. 안전한 경계를 확보하지 못한 원격 되감기는 전수 후보 경로로 유지할 수 있다.
- 후보 반환을 기존 수집 순서로 복원한다. 순서를 바꾸면 기존 첫 피격 대상과 같은 팀 차단 동작이 달라진다.

단위 3a sphere·선분 재사용을 검증하고 사용자 진행 확인을 받은 뒤 3b 구현 방식을 확정한다. 기존 분리력·비행 이동 소비처의 동작은 별도로 보존한다.

### 첫 적용 범위

- 서버의 적 직격 후보 루프에만 적용한다. 현재 EnemyQuery와 같은 집합을 사용해 지상/비행, Actor/PureEntity, 활동 대역, Dying 포함 여부를 보존한다. 같은 팀도 차단 대상이므로 제외하지 않는다.
- 첫 버전은 `!Proj.bInstigatorIsRemoteClient && clamp(CachedRewindSeconds, 0, MaxPingRewindSeconds) == 0`인 현재 위치 판정에 적용한다. 원격 발사는 ping 0이어도 PureEntity 보간 지연이 가산될 수 있으므로 전수 경로다. 반사 후에는 갱신된 발사자/되감기 플래그로 다시 선택한다.
- 플레이어 판정/패링은 소수 대상이므로 기존 전수 경로다. 클라이언트는 복제 버블 안 엔티티와 로컬·관전 Ghost의 sphere/정밀 경로를 유지한다. 복제 버블은 후보 수를 줄이지만 프레임 선분의 공간 조회를 대체하는 완전한 필터는 아니므로 클라이언트 이득/불필요함을 확정하지 않는다.
- 스플래시·조준·근접에는 이번 단위에서 연결하지 않는다. 현재 위치를 쓰는 스플래시는 후속에서 같은 인덱스를 활용할 수 있다.

### 저장과 조회

기존 등장방형 축소 행의 셀 배치·카운팅 정렬 코어를 활용하고, 이동/분리용 subsystem과 **데이터 인스턴스를 분리**한다. 투사체용은 HitDetection이 이미 모은 `Enemies`의 캡슐 중심과 수집 배열 인덱스로 판정 시점에 구축한다. 기존 이동 전 격자의 위치·Dying 제외를 그대로 참조하지 않는다. 적용 가능한 탄이 있을 때만 프레임 1회 지연 구축하고 배열/셀 레이아웃 메모리를 재사용한다. 기존 이동/비행 분리 소비처의 조회 동작 변경은 피한다.

초기 해상도는 기존 `EnemyGridLatResolution=128`을 활용한다. 셀 한 변은 약 `PI * 실제 반지름 / 128`이며 DefaultGame의 SphereRadius 30,000cm를 기준으로 약 736cm다. 후보 수와 구축/조회 비용을 먼저 측정하고 별도 해상도 설정은 실측 필요성이 있을 때만 추가한다.

고정 거리나 현재 끝점 반경이 아니라 **월드 hit로 잘린 프레임 선분 전체**를 감싼 구를 조회한다. A=PreviousPos, B=clipped SegmentEnd, M=(A+B)/2, L=|B-A|, Hmax=max(모든 수집 캡슐의 HalfHeight, Radius)라 할 때:

`조회 중심 = M`, `조회 반경 R = L/2 + Hmax + HitRadius + 작은 수치 여유`.

예를 들어 L=200cm, Hmax=96cm, HitRadius=5cm이면 R≈201cm다. 이는 예시이며 고정 튜닝 값이 아니다. 고도가 다른 지상·비행도 같은 구면 셀에 들어가 과다포함될 수 있으나, 기존 sphere→정밀 캡슐 판정으로 제외한다.

원점을 포함하지 않는 조회 구는 `asin(R / |M|)`의 보수적 각반경으로 바꾼다. 기존 `R / |M|`·행 중심 cos 근사 대신 정확한 구면 cap의 위도/경도 범위로 조회하고, 극 포함 시 경도 전체·경도 이음매 wrap을 처리한다. 원점 엔티티는 별도 항상 포함 목록으로 누락을 막는다. 구가 원점을 포함하거나 예상 방문 셀 수가 전체 적 수 이상인 경우는 전수 경로로 돌린다. 후보 배열은 중복을 제거하고 수집 인덱스 오름차순으로 복원한 뒤 기존 루프를 실행한다. 가까운 순서로 재정렬하지 않으므로 기존 첫 피격과 적→플레이어 판정 순서를 유지한다.

### 검증과 후속 범위

구면 cap/셀 경계·극·경도 이음매·고도 차·원점·긴/점 선분·캡슐 크기 혼합을 회귀 검사한다. 전수 sphere/정밀 기준의 모든 hit 후보가 그리드에 포함되는지, 첫 피격 대상과 출력 위치가 같은지 대조한다. 원격/핑 되감기·반사·패링·월드 clip의 경로 선택도 검증한다. 빌드/관련 자동화와 동일 패키지 Off/On 반복으로 구축/조회/정렬 비용·후보 수·fallback 비율·전체 투사체 CPU·프레임 P95를 측정해 채택한다. 검증용 전수 대조는 기본 실행에서 끈다.

원격 발사까지 좁히려면 최근 히스토리와 배회 곡선까지 감싼 보수적 경계가 필요하다. 최대 속도×ping이나 과거 샘플 끝점만으로는 순간 이동·넉백·배회 평가를 포괄하지 못하므로 첫 버전에는 넣지 않는다. 이번 안의 원격 발사 최적화 범위는 기존 sphere/선분 재사용까지다.
