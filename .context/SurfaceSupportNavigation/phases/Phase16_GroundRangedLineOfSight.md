## 1. 조사 범위와 확인 사실

첫 개선안의 대상은 기존 재현에서 언급된 `GroundSupport`·`Ranged`·`PureEntity`다. 비행·벽보행에는 이미 사선 차단 반응이 있다. Actor 승격형은 공격을 GAS가 담당하므로 같은 fragment 플래그만으로 적용할 수 없다. Actor 승격형까지 포함할지는 별도 범위로 판단한다.

초기 조사는 소스와 인계 문서를 대상으로 했으며, 당시 실제 Config 에셋의 현재 값·새 PIE 재현·성능은 확인하지 않았다. 구현 시 확인 결과는 §6을 따른다. 첫 PIE의 지상 원거리 정지 관찰이 사선 재배치 부재 때문이었다고 확정하지 않는다.

| 접점 | 확인한 동작 |
|:---|:---|
| `LNPEnemyProcessors.cpp`의 `TargetFollow`·`Movement` | 사선과 무관하게 `ComputeStopDistance(AttackRange)` 안에서 정지한다. |
| `LNPEnemyStateTreeProcessors.cpp`의 `SteeringTask`·`AttackTask` | 사거리로 공격 상태에 진입하고 요청을 세운다. StateTree는 신호가 있어야 틱한다. 공격 Task의 `DesiredSpeed=0`과 이동 프로세서의 실제 정지 판정은 별개다. |
| `LNPEntityAttackProcessor.cpp` | `bRequireLineOfSight`가 켜진 순수 엔티티 원거리 공격은 시작 전에 검사한다. 막히면 `bLineOfSightBlocked=1`, 재시도 간격은 0.25초다. 현재 Config 코드 기본값은 false이며 지상 적용은 과거에 유보했다. |
| `LNPEntityAttackShared.h`의 `HasClearShotFrom` | 실제 사격과 같은 총구·조준점을 사용한다. 몸 중심→총구 보정과 보정 총구→조준점으로 exact raycast 2회다. |
| `LNPEnemyPathProcessor.cpp` | `MoveTarget.DistanceToGoal`이 도착 범위면 경로를 취소한다. 목표가 있으면 기존 직선 보행 검사·A*·scheduler/cache·도달 불가 접근점을 사용한다. |
| 비행·벽보행 이동 | 사선 차단에 반응하지만 비행의 측면 이동과 벽보행의 매 프레임 사선 검사를 지상에 그대로 가져올 필요는 없다. |

## 3. 추천안 A의 최소 동작

1. 평소에는 기존 사거리까지 접근한다. 공격 시작 전에 공용 사선 게이트로 검사한다.
2. 막혔으면 공격을 시작하지 않고 기존 지상 추격을 재개한다. 이때 목표는 사거리 경계의 가상 정지점 대신 플레이어 쪽 기존 Nav 목표로 둔다. 별도 사격 위치 탐색이나 새 A*는 만들지 않는다.
3. 차단 중이고 사거리 안이면 기존 공격 요청이 이어지게 한다. 재검사는 공격 게이트 한 곳에서 0.25초 간격으로 한다. 이동 프로세서에 같은 raycast를 추가하지 않는다.
4. 게이트가 통과해 공격을 시작하면 기존 공격 위상 정지로 즉시 멈춘다. 공격 뒤에도 사거리 안에서 그 자리를 유지하도록 처리한다. 우회 중 원래 정지 거리보다 멀어진 경우에도 사거리 경계로 다시 걷지 않게 해야 한다.
5. 사거리 이탈은 기존 추격, 타겟 변경·소실은 사선 관련 기억 초기화로 처리한다. 새 타겟에 이전의 차단/자리 유지 결과를 재사용하지 않는다.
6. 실제로 이어진 길이 없으면 기존 도달 불가 접근점까지만 간다. 경로 실패나 접근점 도착 뒤 매 프레임 같은 요청을 다시 제출하지 않는다. 모든 장애물에서 사선을 확보하는 것을 완료 조건으로 두지 않는다.

`bLineOfSightBlocked`만 이동에서 읽는 한 줄 수정으로 끝내면 안 된다. 목표 생성·경로 취소·이동 정지가 같은 조건을 써야 하고, 재배치 중에도 공격 요청 신호가 유지되어야 한다. 사선이 트였다는 사실과 아직 검사하지 않았다는 상태도 혼동하지 않는다. 최소한의 서버 전용 상태로 차단 중 접근과 사격 자리 유지를 구분하되 별도 전술 상태 머신은 만들지 않는다.

## 4. 비용 예상과 작업량

- 지속 차단 개체 N기가 모두 재시도할 때 사선 판정은 초당 약 `4N`회, 현재 공용 함수의 raycast는 약 `8N`회다. 100기면 약800회/초다. 정상 사격 시 검사·실제 이동 충돌·경로 비용은 별도다.
- 재시도 간격 때문에 사선이 트인 뒤 인식까지 약0.25초가 걸릴 수 있다. 이동 속도에 따른 지나침도 PIE에서 확인한다. 먼저 매 프레임 검사로 확대하지 않는다.
- 기존 공격 프로세서는 게임 스레드에서 실행된다. 위 호출 수만으로 CPU ms나 무시할 수 있는 비용을 보장하지 않는다. 한꺼번에 재시도할 때의 집중도도 확인한다.
- 길찾기는 기존 scheduler 예산·경로 공유·재요청 제한을 유지한다. 기존에 멈췄던 NPC가 이동하므로 총비용 증가는 사선 검사만으로 설명할 수 없다.
- 새 Nav 데이터·베이커·재베이크는 필요하지 않을 것으로 예상한다. 네트워크에는 이동 결과를 기존 경로로 전달하고 새 사선 상태를 복제하지 않는 안이다.
- 구현·고정 회귀·빌드·PIE를 합쳐 **1~2세션 추정**이다. 이는 확정 일정이 아니며, Actor 승격형 적용·후보 B·성능 문제의 추가 최적화는 포함하지 않는다.

## 5. 구현 시 검증 순서

1. 실제 지상 원거리 Config·사거리·공격 모드와 기존 Ridge WIP 재현을 확인한다. 사용자 수동 PIE가 빠르면 새 자동 재현 장치보다 먼저 요청한다.
2. 원인이 일치하면 추천안 A를 구현한다. 고정 회귀는 차단 중 접근/공격 금지·사선 통과 후 자리 유지·타겟 변경 초기화·재시도 간격을 검증한다. 실제 경로가 없는 경우도 유지한다.
3. 기존 SurfaceNavigation 회귀·Editor/Game 빌드 뒤, 작은 바위/벽 모서리·우회 중 거리가 증가하는 구간·다른 층/섬을 수동 PIE로 확인한다. 근접·비행·벽보행과 분리력의 기존 동작을 보존한다.
4. 리슨2P와 실제 지상 교전 부하에서 query 수·경로 요청·게임 스레드/프레임 비용을 확인한다. 지상 활성0인 기존 Production 결과는 이 변경의 비용 근거로 쓰지 않는다.

구현 후보는 `LNPEnemyProcessors.cpp`·`LNPEnemyStateTreeProcessors.cpp`·`LNPEnemyPathProcessor.cpp`와 최소 상태/공용 조건, 대상 Config다. 정확한 변경 파일 수와 에셋 범위는 실제 Config 확인 뒤 정한다.

## 6. 후보 A 구현 기록

- 실제 `/Game/Enemy/DA_Enemy_PureEntity_Ranged01`은 지상·PureEntity·원거리, 사거리1000cm·속도600cm/s이며 사선 플래그가 false였다. 해당 플래그만 true로 바꾸고 나머지 공격 설정 동일성을 재조회했다. 저장 전 사본은 `Saved/Profiling/Phase16/GroundRanged/Backup/`에 보존했다.
- `UsesGroundLineOfSight`·`GetChaseStopDistance`를 목표 생성·실제 이동의 공통 조건으로 쓴다. 차단 중에는 정지 거리0으로 기존 플레이어 쪽 경로를 요청하고, 사격 자리를 확보하면 사거리 전체를 정지 범위로 쓴다. 베이커·Nav 데이터·경로 알고리즘은 바꾸지 않는다.
- 공격 게이트가 기존0.25초 간격으로만 검사하며 결과에 따라 자리 유지 비트를 갱신한다. 이동 프로세서는 추가 사선 검사를 하지 않는다. 최초 차단 프레임은 다음 Follow/Path가 접근 목표를 준비할 때까지 정지한다.
- 차단 중에는 우회로 원래 정지 거리 밖으로 나가도 사거리 안의 StateTree 공격 요청 신호를 유지한다. 기존 AttackTask가 그대로 요청하므로 StateTree 에셋/태스크·Path 프로세서 변경은 필요하지 않았다.
- fragment의 서버 전용 타겟 handle·자리 유지 비트로 이전 타겟 결과를 초기화한다. 타겟 변경·Confirmed 상실·사거리 이탈이 해제 조건이다. 분리력은 바꾸지 않는다.
- `NavReport`에 `losBlocked`·`holdFire`·`attackPhase`를 추가했다. 고정 회귀는 기존 캐시/Blocker 픽스처에서 실제 Follow·공격·이동 프로세서를 실행하는 `EnemyLineOfSight.GroundChase`다. Nav 탐색기 자체와 StateTree 신호 소비의 종단 간 동작은 실제 PIE에서 추가 확인한다.
- Live Coding Success. `EnemyLineOfSight.Gate`·새 `EnemyLineOfSight.GroundChase` **2/2 Success**(오류/경고0). 최초 컴파일의 테스트 snapshot 비공개 접근 오류는 기존 테스트와 같은 friend 선언으로 해결했다.
