## 1. 목표와 범위

테스트 geometry가 아닌 실규모 레벨 디자인 옥탄트에서 지금까지의 설계(다층 Support·접힌 sheet·여러 portal·지하 대형 공동·headroom·활동 대역·벽보행·동적 연결)가 성립하는지 검증하고, 실제 콘텐츠 기준의 성능·메모리 기준선을 확정한다.

2026-10-06 사용자 결정:

- **품질 기준**: 실규모 레벨 디자인. 동선·스케일·구조는 최종 수준으로 만들고 외형은 단순 머티리얼 블록아웃이다. 아트 패스는 같은 규약의 메시를 1:1로 교체하는 후속 작업이며 이 Phase 범위가 아니다.
- **옥탄트 수**: 새 옥탄트 2개. 지하 공동의 입구 조합을 서로 다르게 한다. `Meadow_00`은 풀에 남긴다.
- **제작 주체**: Claude가 메시 생성(Blender MCP·에디터 명령)과 LVI 배치를 맡고, 사용자는 PIE로 동선을 검토해 피드백한다.

제작 규칙은 `design/TerrainContract.md` §5·§6·§6-1·§7과 D-070·D-071을 따른다. 새 엔진 기능이나 Support·Nav 구조 변경은 범위가 아니다. 콘텐츠가 드러낸 결함은 최소 수정하고, 설계 변경이 필요하면 사용자 확인 뒤 별도 단위로 둔다.

각 구현 단위를 검증하고 문서에 결과를 기록한 뒤 사용자에게 다음 단위 진행을 확인한다. 라이브 에셋 작업이 필요하면 즉시 MCP 연결(에디터·Blender)을 요청하고, 전체 빌드가 필요하면 에디터 저장·종료를 요청한다. 빠른 확인은 별도 자동화 장치를 만들기 전에 사용자 PIE 플레이를 요청한다.
