> 상태: 진행 중 — 단위 2 완료(Bastion_00 1차 확정, 레이아웃 규칙 검사·검토 도구 도입), 단위 3 대기(2026-10-07)
> 착수일: 2026-10-06
> 선행 조건: Phase 7c·8·12·13·14 완료

## 1. 목표와 범위

테스트 geometry가 아닌 실규모 레벨 디자인 옥탄트에서 지금까지의 설계(다층 Support·접힌 sheet·여러 portal·지하 대형 공동·headroom·활동 대역·벽보행·동적 연결)가 성립하는지 검증하고, 실제 콘텐츠 기준의 성능·메모리 기준선을 확정한다.

2026-10-06 사용자 결정:

- **품질 기준**: 실규모 레벨 디자인. 동선·스케일·구조는 최종 수준으로 만들고 외형은 단순 머티리얼 블록아웃이다. 아트 패스는 같은 규약의 메시를 1:1로 교체하는 후속 작업이며 이 Phase 범위가 아니다.
- **옥탄트 수**: 새 옥탄트 2개. 지하 공동의 입구 조합을 서로 다르게 한다. `Meadow_00`은 풀에 남긴다.
- **제작 주체**: Claude가 메시 생성(Blender MCP·에디터 명령)과 LVI 배치를 맡고, 사용자는 PIE로 동선을 검토해 피드백한다.

제작 규칙은 `design/TerrainContract.md` §5·§6·§6-1·§7과 D-070·D-071을 따른다. 새 엔진 기능이나 Support·Nav 구조 변경은 범위가 아니다. 콘텐츠가 드러낸 결함은 최소 수정하고, 설계 변경이 필요하면 사용자 확인 뒤 별도 단위로 둔다.

각 구현 단위를 검증하고 문서에 결과를 기록한 뒤 사용자에게 다음 단위 진행을 확인한다. 라이브 에셋 작업이 필요하면 즉시 MCP 연결(에디터·Blender)을 요청하고, 전체 빌드가 필요하면 에디터 저장·종료를 요청한다. 빠른 확인은 별도 자동화 장치를 만들기 전에 사용자 PIE 플레이를 요청한다.

## 2. 착수 시 확인한 기준선

- 옥탄트는 `LVI_Octant_Meadow_00` 1개다(지각 `SM_Octant_Meadow_00_R30000`, `BP_OctantGenerator` Radius 30,000·Subdivisions 200·Magnitude 18,000·Frequency 0.0002). 나머지 LVI는 회귀·확인용 fixture다.
- 아트 에셋이 없다. 섬·경사로는 `Scripts/Blender/GenerateFloatingIslands.py`, 동굴 키트는 `LNP.SurfaceNav.BuildCaveKit` greybox, fixture 입체 구조물은 C++ 에디터 빌더, 프랍은 PCG 기본 도형(`DA_OctantTheme_Meadow`)이다.
- 지각 입구 절단은 `LNP.SurfaceNav.PlaceCaveKit`(`LNPCaveKitPlacer`), 지각 일체형 경사로는 `LNP.MeshTerrain.RadialRamp`, 베이크는 `LNP.SurfaceNav.BakeOctant`·`LinkPoolSurfaceData`다.
- 풀 선택(`LNPOctantSpawnSubsystem`)은 아직 slot 순서 greedy다. 새 definition이 모두 전체 slot을 허용하면 문제없고, slot mask를 다르게 줄 때만 D-043 제약 할당이 선행 조건이다.
- `Guide_OctantLevelInstance.md`는 25,000cm·`Maps/LevelInstances/` 기준의 옛 절차이며 Surface 태그·베이크·definition 등록 단계가 없다. 단위 1에서 실제 절차로 갱신한다.
- 성능 기준은 Phase 14 최종 패키지(Meadow, D-076 편성, frame P95 10.71/10.67ms)다. 측정 스크립트는 `Scripts/Profiling/RunPhase13Gate.ps1`이다.
- 시작 시 `git status --short`는 비어 있었다.

## 3. 옥탄트 구성안

이름과 구성은 2026-10-07 사용자 확인으로 확정했다. 단위 2 제작에서 바뀐 점은 A 표 아래에 적는다.

좌표는 옥탄트 중앙(위도 35.26°·방위 45°) 기준 로컬 호 길이(m)다. X는 위도 증가(북), Y는 방위 증가(동). 이음매 보존 밴드(이음매 평면에서 55m) 때문에 고유 지형은 중심 반경 약 110m 안에 둔다.

**A `Bastion_00`** — 성곽 도시

```
            N(+X)
   I1(섬,25m,경사로)        I2(섬,35m,앵커만)
        ┌──────── 성벽 R≈60m, 높이 8m, 성벽 위 통로 ────────┐
        │  B1(2층)      [북문]        B2(3층)              │
  [서문]│              T1 나선탑                            │[동문]
  ↓긴   │         (광장 Pad R35m, 수직통로 S1)               │
  경사로│  B4(폐허)     [남문]        B3(긴 홀, 문3)         │
        └────────────────────────────────────────────────┘
                                         Mesa01(85,-55)
   지하 C1: 광장 아래 40m, 70×50m, 천장 18m, 안에 2층 구조물
            입구 = 서문 밖 긴 경사로(지상 적 진입) + 광장 수직 통로 S1(앵커)
```

단위 2 제작에서 바뀐 점(2026-10-07, 반복 1에서 아래 "거인의 성채"로 다시 바뀌었다):

- 긴 경사로는 곧은 직선이 아니라 반지름을 선형으로 줄이며 오르는 구면 경사로(수평 69m, 그 지점 Up 기준 약 30°)다. 접평면 직선으로 놓으면 곡률 때문에 공동 쪽 끝이 33° 넘게 가파르다.
- 동적 요소는 탑 꼭대기와 I2를 잇는 수평 셔틀 패널 1개다. S1 수직 엘리베이터는 아래에 선 캐릭터와 겹치는 문제를 피하려고 쓰지 않았다. I2는 셔틀과 앵커로 간다.
- 메사 꼭대기 Pod는 뺐다. 윗면 반경 약 7.6m가 Pod 주변 판정(250cm 안전 반경, NeedsExact)을 통과하지 못하고, Pod 스폰 반경 15m보다도 좁다.
- 앵커 위치는 지형에 맞춰 두고 거리가 먼 앵커는 마커별 최대 거리(`GrappleMaxDistance`)로 맞춘다. 지형을 그래플 거리에 맞추지 않는다(사용자 지시).

**A `Bastion_00` — 거인의 성채(2026-10-07 반복 1~5, 1차 확정)**

공통 기준: 지면 위 200m·아래 100m를 채운다(옥탄트마다 +240/−150, +180/−130도 시험). 옥탄트마다 멀리서 보이는 메인 무대(보스 자리) 하나. 대부분 1~2면이 무너진 폐허 건물, 모든 건물·다리·섬에 앵커, 지형을 앵커 거리에 맞추지 않는다.
