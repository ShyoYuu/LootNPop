# Grove_00 제작 계획 — 거목과 뿌리 사이의 지상 순환

> 작성: 2026-11-08
> 상태: 사용자 컨셉 채택, 제작 미착수
> 범위: 정식 아트 적용 전 로우폴리 공간·이동·전투 프로토타입

## 1. 목표와 기존 테마와의 차이

핵심 경험은 **공터에서 교전 → 큰 줄기로 사선 차단 → 옆 공터나 측면으로 이동 → 재교전**이다. 이어진 지면에서 달리기·회피·우회가 자연스럽게 연결되는 옥탄트를 만든다.

Pyramid의 실내 복층, Hollow의 깊은 협곡·공동, Bastion의 중앙 정상 상승, Acropolis의 부유섬 횡단과 구별한다. Grove의 주요 목적지는 지상에서 보행으로 연결한다. 훅은 전투 이탈·횡단·복귀·선택 지름길에 사용한다. 수관 플랫폼 상승이 주 경로가 되지 않게 한다.

정식 나무·잎·풀 에셋 없이 큰 다각기둥 줄기, 쐐기형 뿌리, 단순 지면으로 공간 역할을 검증한다. 바람·수목 파괴·새 은신 시스템을 추가하지 않는다.

월드 반지름은 30,000cm 고정이다. Meadow 기준 이음매와 실제 베이크 seam 계약을 보존한다. 경계 보존 띠·전이 띠는 제작 시작 시 선택한 제작 경로에 명시하며, 기존 옥탄트의 수치를 추측해 복제하지 않는다. 좌표는 옥탄트 로컬 X/Y/H이며 H는 구 중심 쪽으로 증가한다. 폭·경사·훅 거리는 최종 구면 투영 후 측정한다.

기존 승인 네 옥탄트의 지형·마커·재질과 전역 이동/스폰 설정은 보존한다. Meadow는 플레이 풀 제외 의향이 있으나 이 문서 작성 시 실제 풀에서는 미제외다. 새 세션은 현재 풀을 다시 읽고 Meadow 원본·테스트 fixture를 삭제하지 않는다. Ridge 작업을 함께 진행하지 않는다.

## 3. 공간 초안

아래는 배치 원칙이다. 구역 수·위치·치수·Pod 수는 평면도와 대표 구역을 확인한 뒤 정한다.

| 구역 | 역할 | 연결·시야 |
|:---|:---|:---|
| 세 경계 진입부 | 이웃 옥탄트에서 들어왔을 때 가까운 목표 제공 | 첫 공터까지 보행, 돌아가는 경사도 자연스럽게 연결 |
| 큰 거목 사이 전투 공터 | 회피·Pod 사수·비행 적 교전 | 오래 머무는 공터에 서로 다른 방향의 보행 진입/이탈 연결 |
| 줄기 둘레와 뿌리 능선 | 사선 차단·측면 진입·선택 지름길 | 좁은 미로를 만들지 않고 이웃 공터와 다시 합류 |
| 얕게 낮아진 지면 | 주 경로 이탈과 넉백 후 회복 | 걸어서 돌아오거나 발견하기 쉬운 복귀 훅 사용 |
| 갈라진 고목 아래 보스 공터 | 멀리서 읽히는 목적지 | 주요 공터와 경계 접근에서 고목 실루엣 확인, 지상으로 접근 |

평면은 공터들이 고리로 연결되고 중간 횡단이 있는 형태부터 검토한다. 단면은 연속 지면과 낮은 뿌리 경로가 중심이다. 뿌리 위 높이차는 초기 후보 약 5~20m로 검토하되 확정 규격으로 취급하지 않는다. 뿌리 밑 통과를 넣으면 현재 비행 편성의 실제 머리 공간을 확인하고, 낮은 천장으로 Pod 후보를 잃는지 검사한다.

줄기는 몸체를 숨길 만큼 크되 공터 전체를 막지 않게 배치한다. 수관으로 상공을 덮지 않는다. 벽보행 적이 줄기·뿌리에서 전투 지면으로 합류할 연속 표면과 짧은 경로를 만든다. 적이 장애물 뒤에 갇혀 공격하지 못하는 결과를 엄폐 재미로 해석하지 않는다.

## 4. Pod·훅·색상

Pod는 공터 중앙·줄기 옆·뿌리 합류부 등 접근 양상이 다른 공간에 배치한다. 사수 영역 안에서 회피할 여유와 복수의 적 접근 방향을 확보한다. 한 줄기로 모든 공격을 차단한 채 안전하게 사수하는 배치를 피한다. 실제 Pod 편성과 스폰 여유는 현재 설정에서 읽으며 총량을 늘리거나 스폰 필터를 완화하지 않는다.

훅은 큰 장애물 옆을 지나 다른 공터에 착지하는 횡단, 짧은 상승 지름길, 얕은 하층 복귀에 한정해 필요 위치부터 둔다. 같은 목적지의 중복 앵커를 늘리지 않는다. 다음 착지면과 다음 보행 방향을 확인하고, 시야·캡슐 접근·종료 관성·착지를 따로 검증한다. 수동 훅만 사용할지는 기존 `LNP.Grapple.AuthoredOnly` 정책을 확인한 뒤 결정한다.

프로토타입 지면은 **회녹색 sRGB `#718767`**을 시작값으로 한다. 테마 소유 재질을 사용하고, 훅·Pod·장치 기능색은 기존 규칙을 따른다. 조명 아래 식별성은 PIE에서 확인하며 정식 아트 색상으로 확정하지 않는다.

## 5. 제작 순서와 단계별 통과 기준

1. **기준선·도면:** 현재 에디터/PIE·풀·작업 트리를 확인하고 대상 파일을 복구 저장한다. 평면도·단면도·출발→도착 연결표에 세 경계, 보스 실루엣, 공터, 회복 경로를 기록한다. 확인: 순환과 측면 선택이 도면에서 설명되며 기존 수직 테마의 복제가 아니다.
2. **대표 구역:** 공터 두 곳, 큰 줄기, 뿌리 우회로, Pod 전투 공간, 선택 훅 하나를 만든다. 구역별 최종 외피 소유자를 코드 또는 Blender로 정한다. 확인: 걸어서 왕복·사선 차단·측면 재진입·NPC 합류·넉백 후 복귀가 성립한다.
3. **사용자 대표 구역 확인:** 실제 플레이로 더 빨리 판단할 수 있는 시야·카메라·전투감은 짧은 PIE 동작을 요청한다. 필요한 최소 베이크로 런타임 원본을 맞추되 이를 충돌 검증 완료로 기록하지 않는다. 성공 기준: 엄폐 뒤에서 이웃 공터로 자연스럽게 이어지고 이동이 좁은 틈에 자주 막히지 않는다.
4. **전체 구성:** 확인한 공간 문법으로 나머지를 제작한다. 원본은 `Art/Octants/Grove_00/`, 생성/반입 코드는 `Scripts/`의 테마 전용 파일, 중간본은 `_WorkInProgress`, 복구·FBX·로그는 `Saved/SliceOctant/Grove_00/<Version>/`로 구분한다. 확인: 지형 중복 소유·내부 면·노출 틈·갇힘을 검사하고 지각과 접합한다.
5. **UE 반입·충돌·베이크:** 최종 좌표·충돌 역할·양방향 접합·훅 접근/착지·Pod 바닥/머리 공간을 검사한다. 기존 Support/Nav/Spawn 베이커를 사용하고 seam·source 현재성·결정론·혼합 정의/편성 검사 중 적용 가능한 기존 검사를 실행한다. 새 기능이 없으면 테스트 장치를 먼저 만들지 않는다.
6. **풀 통합·마지막 PIE:** 최종 LVI·DA를 묶어 기존 정의를 보존하고 한 번만 등록한다. `AllowedSlotRotations=255`와 현재 seam signature를 확인한다. 풀의 최신 상태를 다시 읽어 Ridge 등 다른 세션의 등록을 덮어쓰지 않는다. 8slot 게시·경계 이동·전체 탐색·Pod 교전·복귀를 확인하고 문서 상태를 갱신한다.

현재 `BuildSliceOctant Grove_00`은 지원된다고 가정하지 않는다. 첫 단계에서 기존 C++ 빌더 확장과 독립 Blender/조립 경로 중 단순한 경로를 선택해 기록한다. MCP 콘솔 기능 부재를 메우기 위한 새 도구를 만들지 않는다. 에디터를 공유하는 세션의 레벨 전환·베이크·풀 저장은 동시에 실행하지 않는다.

## 6. 완료와 인계

- 기존 옥탄트와 테마별 지면 재질을 보존하고, 새 지형·마커·풀 정의·DA가 함께 저장된다.
- 경계 진입, 공터 순환, 측면 우회, 훅, 실패 후 복귀가 구분된 검토점에서 확인된다.
- 비행·벽보행·지상 NPC의 출현과 실제 합류·공격을 구분해 기록한다.
- 원본/반입/충돌/베이크 자동 검사와 사용자 PIE 결과를 나누고 미관측 범위를 명시한다.
- 정식 아트·새 보스 패턴·보상 밸런스 완료로 확대하지 않는다.

다음 인계에는 버전, 형상 소유 파일, 도면/연결표, 검토점, 베이크 지표, 자동 검사 결과, 사용자 확인, 남은 구역 하나를 남긴다. 현재는 문서만 존재하며 원본·UE 에셋·DA·검사·PIE는 모두 미착수다.
