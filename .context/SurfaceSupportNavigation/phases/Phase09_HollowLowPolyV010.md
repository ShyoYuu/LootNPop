# Hollow 전체 단순화 V010 제작·검증 상태

2026-10-10. 실행 기준은 [전체 재제작 지시](Phase09_HollowLowPolyRebuild.md)다. **V010 생성·베이크 성공 뒤 정식 검사270건이 실패했다. 후속 수정은 [V016](Phase09_HollowLowPolyV016.md)과 최신 [V017](Phase09_HollowLowPolyV017.md)을 따른다.** 아래는 V010 제작 당시 기록이며 기존 V015/V006의 사용자 확인 결과를 새 배치에 승계하지 않는다.

## 형상 소유권과 복구

- `Scripts/Blender/BuildHollowLowPoly.py`: 내부 지면·협곡·양쪽 절벽·잔도·전투 굴·공동·수직 입구·숨은 뒷길·산 왕복 경사·동쪽 외곽 진입을 한 닫힌 외피에서 만든다. 판·직육면체·경로 단면으로 시작하고 순차 Boolean으로 내부 면을 제거한다. 장식용 밑동과 국소 보정 메시를 추가하지 않았다.
- `LNPSliceOctant.cpp`: Meadow 기반 지각/이음매, 닫힌 사각 판 4개(Ascent/Arena/CaveLift/Shuttle), Pod8·앵커26·패널2·블록2·램프6·검토 지점29개를 소유한다. 옛 Hollow의 세부 부품 spec과 `ReplaceBackPocketRegion/ReplaceEastRimRegion`은 새 소유 구조로 대체했다. Bastion 생성 경로는 유지한다.
- 지각 절단 경계는 접평면 육각형의 96%다. 내부 몸체의 외곽 4%는 H−80cm로 지각 아래에 매입하며 Shell만 소유한다. 공유 이음매 15m와 전이 20m는 유지한다. 실제 조립 접합·seam 게시 검사는 별도다.
- UE 후보: `/Game/Maps/OctantWorkflow/HollowLowPolyV010`. production: `/Game/Maps/Hollow_00/Authored/SM_Hollow_00_LowPolyV010_*` 8개. 빌더는 명시한 버전 접두사만 배치해 이전 버전/redirector의 중복 배치를 막는다.
- 생성 원본과 FBX·manifest: `Saved/SliceOctant/Hollow_00/LowPolyV010`. 편집 가능한 operand는 `Sources.blend`, 최종/역할 메시를 포함한 사본은 `HollowLowPoly.blend`다. 스크립트에서 재현 가능하며 Blender의 기존 장면은 보존했다.
- 작업 전 코드·전체 Hollow 에셋 복구본: `Saved/SliceOctant/Hollow_00/LowPolyV001/Before`. 이전 production Authored4개는 UE move로 `Authored/Archive/BeforeLowPoly`에 보존했다. 다른 작업의 dirty 파일은 되돌리지 않았다.

## 평면·단면

좌표는 접평면 X/Y/H cm다. 실제 거리·폭은 구면 투영 후 작아지거나 커지므로 아래 수치만으로 캡슐 여유를 판정하지 않는다.

| 공간 | 배치·단면 | 역할 |
|:---|:---|:---|
| 내부 지면 | 외곽 X±15000, 육각형; H0, 밑면−15000 | 틈 없는 큰 몸체와 외곽 접근 |
| 굽은 협곡 | 서쪽 X−12000에서 동쪽 X12500; 바닥 H−7500 | 하강 전투와 양쪽 훅 이동 |
| 서쪽 절벽 | Y−7000~−3500, 윗면 H6000 | 왕복 보행 정상·Pod1·전투 굴6 |
| 동쪽 절벽 | Y3500~7000, 윗면 H10000 / 안부 H4500 | 측면 높이차·Pod2·전투 굴7 |
| 중간 잔도 | H−5000~7500의 닫힌 얇은 판 | 단계별 훅 착지·횡단 패널 접안 |
| 주 공동 | H−12000~−9000, L자 평면 | Pod3/4·전투·두 수직 입구 |
| 뒤편 굴 | (6000,−5300,H1500) | Pod8·서쪽 상층과 연결 |

서쪽 보행은 세 개의 긴 상승 구간과 수평 회전 구간으로 H0→2000→4000→6000을 연결한다. 동쪽은 (−13500,13500,H0)→(4000,11000,H2000)→(4000,8500,H2000)→(−6000,8500,H4500)→안부로 연결한다. 뒷길은 공동 서쪽→(−13500,3500,H−9500)→(−13500,−8500,H−4500)→(−3500,−8500,H−2000)→(−3500,−11500,H−2000)→(−12500,−11500,H0)→입구다. 뒷길 폭은 접평면18m·높이14m이며 회전부가 같은 단면을 공유한다.

## 검사·실패 경위

- V003은 생성 성공 후 공동 일부 Support 정점의 int16 좌표 상한32767cm 초과로 베이크가 실패했다. 공동 북서쪽을 제거한 L자 평면과 뒷길 배치로 해결하고, 모든 출력 Support 정점에 상한 검사를 추가했다. 런타임 좌표 상한은 바꾸지 않았다.
- 제작 중 경로 폭 검사로 별도 회전 cutter의 단차와 협곡 간섭을 찾았다. 단면을 공유하는 경로와 큰 협곡 윤곽 변경으로 해결했다. 중심선 경사만으로 횡경사를 보장할 수 없어 최종 면 법선도 검사한다.
- V009은 Pod1 아래의 보간 가능한 Support 부재로 베이크가 실패했다. 열린 역할 조각에 공통 `mesh_object`의 법선 재계산을 적용한 것이 원인이다. V010은 닫힌 외피의 winding을 그대로 출력하며 모든 역할 면의 분리 전후 법선 일치를 검사한다. 실패 버전을 검증 통과로 세지 않는다.
- V010: 닫힌 외피64430 tris, 비다양체/방향 불일치/중복/퇴화0·연결 성분1·공유 정점 없는 삼각형 BVH 교차0. Floor/Coarse/Shell 합계가 외피와 같다. 공유 정점끼리의 교차까지 완전 증명한 결과는 아니다.
- 100cm 간격·경로 5개 트랙(접평면 lateral±700/±350/0cm)의 바닥6455곳 누락0, 실제 면 최대 경사34.393°. 경로 가장자리/중심선 방향 최대29.134°. 전체 접근 가능한 외피나 실제 플레이어 통행 완료를 뜻하지 않는다.
- 투영 분할은 공유 모서리 중점의 현 오차4cm 기준이다. 모든 표면의 최대 오차 상한으로 확대하지 않는다. 열린 역할 출력 뒤 법선을 다시 계산하지 않는다.
- UE 8개 메시의 triangle 수 일치, bounds 최대차0.005555cm, 충돌LOD0/별도complex 없음/complex-as-simple/양면false를 재조회하고 저장했다. Live Coding patch_3 Success다. 이후 경로 5개 트랙과 전체 육각형 내부 소유 경계의 양방향 Chaos 캡슐 검사를 추가한 patch_4도 Success이며 아직 실행 전이다.
- 베이크·정식 검사·전체 조립 경계·장치 역할·최종 PIE 결과는 아래 실행 기록이 소유한다. 아직 완료하지 않은 검사를 통과로 기록하지 않는다.
