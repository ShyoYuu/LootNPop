## 1. 목적

1440p 출력에서 GPU 프레임 비용을 **렌더 해상도에 비례하는 몫**과 **적 수에 비례하는 몫**, 그리고 둘 다에 무관한 고정 몫으로 나눈다. 그 비용 곡선으로 GX-002의 운영 조건(내부 해상도·업스케일러)을 정한다. Phase 0 기준선(TSR 100%)은 네이티브 기준으로 그대로 둔다.

## 3. 대조군 선택 — 사용자 확인 필요

로드맵은 "1440p 대조군(적 최소)"을 말하지만, 현재 하네스에는 적 0 편성이 없다. 하네스가 적 밀도를 1로 고정하고(`GetEnemySpawnDensity`), 초기 적 0을 실패로 처리한다(`Prepare`의 `InitialEnemies <= 0`).

| 안 | 방법 | 비용 | 한계 |
|:---|:---|:---|:---|
| **A. 기존 바이너리(권장)** | `RenderSyncDiagPackage_20261108` 그대로, Low(최소 1053)·High(3257) 두 편성으로 적 수 축을 만든다. 해상도는 진단 인자 `-LNPGraphicsDiagnosticCVars="r.ScreenPercentage=N"`으로만 바꾼다 | 코드·빌드·쿡 없음. Phase 0 기준선과 같은 바이너리라 직접 비교 가능 | 적 0 점이 없어 고정 몫은 외삽값 |

## 4. 측정 설계(안 A 기준)

- **요인:** 편성 {Low, High} × 렌더 해상도 {100, 77, 67, 58, 50}% = 10회. 77/67/58/50은 TSR의 Ultra Quality/Quality/Balanced/Performance 비율이다.
- **드리프트 기준점:** 마지막에 Low·100%를 한 번 더 돌린다(11회). 첫 Low·100%와 ±1ms 넘게 다르면 세트 전체를 판정 보류한다.
- **순서:** 해상도 순서대로 돌리지 않고 섞는다(해상도와 시간 경과가 겹치지 않게). 예: L100 → H50 → L67 → H77 → L58 → H100 → L50 → H67 → L77 → H58 → L100.
- **조건:** 회차 하나씩 따로, 워밍업 180초·측정 60초, 회차 사이 냉각 대기(온도 ≤55°C·전력 ≤15W 60초, 2회차부터 최소 300초, 최대 1200초). GPU 텔레메트리 1초 기록. 트레이스는 켜지 않는다(Frame·GPU 절대값이 목적).
- **회차 판정:** 각 회차 1회 측정이며 진단 실행(`performance_eligible=false`)이다. 기준선 3회 중앙값과 섞지 않는다. 집계는 `AnalyzeGraphicsBenchmark.ps1 -AllowPreview`로 하고 `Run.json`의 `effective_cvars`에서 `r.ScreenPercentage`를 확인한다.
- **예상 시간:** 회차당 약 4~5분 + 냉각 약 5분 → 약 1시간 50분. 측정 중에는 게임 창이 화면을 차지하므로 사용자가 PC를 쓰지 않아야 한다(녹화가 아니므로 자리를 비울 필요는 없다).
- **출력:** `Saved/Profiling/Graphics/O2/ResolutionSweep_<날짜>/`. 세션 스크립트(냉각·텔레메트리·순서)는 같은 폴더에 둔다.

## 5. 분석

1. 편성별로 GPU = a + b × (화소 비율)을 맞춘다. a는 해상도 무관 몫, b는 네이티브 화소 비례 몫이다.
2. Low와 High의 차이를 해상도별로 본다. 차이가 해상도와 함께 줄면 적 비용이 화소 점유(셰이딩) 쪽이고, 일정하면 장면 갱신(Lumen 카드·인스턴스 갱신) 쪽이다.
3. 각 해상도에서 Frame이 16.6ms 예산 안에 드는지, 남는 여유(ms)가 얼마인지를 표로 만든다.
4. 패스별 분해는 D0~D2(100/67/50)를 재사용한다. 77·58%가 곡선에서 벗어날 때만 트레이스 1회를 추가한다.

## 6. 화질 확인(사용자, 선택)

같은 패키지 콘솔에서 `r.ScreenPercentage 100/77/67`을 바꿔 정지·이동 화면을 본다. 프로토타입 에셋이라 D5와 같은 이유로 **최종 판정은 하지 않고** 기록만 남긴다.

## 7. 결정안(측정 뒤 사용자 확인)

데이터가 나온 뒤 다음 형태로 GX-002 세부를 정한다. 수치는 측정 결과로 채운다.

- **측정 기준:** 네이티브 100%·TSR(Epic) 유지. 모든 Phase의 전후 비교는 이 조건으로 한다.
- **운영 기본값:** 100% 유지가 기본. 예산을 못 맞추면 렌더 해상도를 유지하는 후보(TSR 히스토리·Lumen, Phase 1 뒤)를 먼저 쓰고, 그래도 부족할 때의 하향 사다리(예: 77 → 67%)를 이 측정으로 미리 정해 둔다.
- **업스케일러:** TSR만 쓴다. DLSS 등 외부 플러그인 도입은 범위 밖이며 필요하면 새 결정으로 다룬다.
