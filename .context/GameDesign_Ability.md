# 어빌리티 시스템 - 게임 기획서

## 1. 개요

전투는 **GAS(Gameplay Ability System)** 기반이다. 플레이어는 기본 무기를 장착한 채 시작하고, LootPod에서 얻은 아이템을 장착·보유해 어빌리티와 스텟을 강화한다.

```
LootPod 루팅 → 아이템 획득 → 장착/보유 → 어빌리티/스텟 강화 → 더 강한 전투
```

---

## 2. 어빌리티 획득 구조

| 아이템 타입 | 슬롯 수 | GAS 연동 |
|:---|:---|:---|
| **무기 (Weapon)** | 1개 | 무기 GA (기본 공격 포함) + 무기 스텟 GE |
| **스킬 - Active** | N개 (설정값, 기본 4) | 키 입력으로 발동하는 스킬 GA |
| **스킬 - Passive** | 무제한 | 조건 충족 시 자동 발동 스킬 GA |
| **버프 (Buff)** | 무제한 | 스텟 GE (기간제·영구) |

---

## 3. 아이템 타입별 상세 기획

### 3.1 무기 아이템 (Weapon)

무기를 장착하면 그 무기의 **고유 기본 공격 어빌리티**가 활성화된다. 무기 종류에 따라 공격 방식이 전혀 달라지는 것이 핵심.

- **슬롯**: 무기 슬롯 1개. 새 무기를 장착하면 기존 무기는 인벤토리로 돌아간다.
- **기본 무기 "피스톨"**: 게임 시작 시 피스톨(`DA_Pistol`)이 장착된 상태다. 기본 무기도 일반 무기 아이템이라 시스템에 특수 처리가 없다.
- **기본 공격 GA**: 무기마다 고유 GA. 교체 시 이전 GA는 제거되고 새 GA가 부여된다.
- **추가 어빌리티**: 기본 공격 외 GA를 더 가질 수 있다(예: 검 → 차지 공격). 미구현.
- **무기 스텟**: `LNPStat::GetStatMetaTable()`의 스텟 7종 어느 것이든 무기가 가질 수 있다.

현재 무기 에셋: `DA_LongSword`(근접), `DA_Pistol`·`DA_Rifle`·`DA_Shotgun`(산탄)·`DA_Launcher`(곡사·폭발), 적 전용 `DA_NPC_Pistol`·`DA_NPC_LongSword`.

컨셉 단계의 무기 예시(미구현):

| 무기 예시 | 기본 공격 특성 | 추가 GA |
|:---|:---|:---|
| 거대 해머 | 근접, 광역 판정, 느린 속도 | 지진 강타 |
| 고무공 발사기 | 원거리, 튀어오름 판정 | 연속 발사 |
| 중력 건 | 원거리, 적 끌어당기기 | 중력장 투사 |

#### 근접 공격 타겟 보정 (2026-08-30)

살짝 빗나가 허공을 베는 답답함을 줄인다. **어느 정도 접근한 상태에서 미세하게 보조**하는 수준이며, 보정 이동이 눈에 띄면 실패다.

- **락온 중**: 락온 타겟 쪽으로 **위치만** 보정한다. 카메라가 타겟을 추적하고 캐릭터는 카메라 정면을 보므로 회전은 건드리지 않는다.
- **락온 해제**: 캐릭터 전방에서 공격 범위보다 조금 넓게 탐색해 **위치와 회전**을 함께 보정한다.
- **이동 입력 중**: 이동 입력이 우선이다. 위치 보정 없이 **회전 보정만** 한다.
- 타겟이 여럿이면 **전방 기준 각도와 거리를 정규화해 가중합한 점수**로 고른다. 두 가중치로 "정면 우선 ↔ 근접 우선"을 튜닝한다.
- 보정량 기준은 무기의 `MeleeIdealDistance`(잘 닿는 거리). **이미 그 안이면 0**이고, 멀수록 커지되 최대 보정 거리·속력 상한에서 잘린다.
- 플레이어 전용이다. 보정 강도는 설정값이며 환경설정 UI가 생기면 그쪽으로 옮긴다.

구현 상세는 [TechDesign_CombatAnimation.md](TechDesign_CombatAnimation.md) §6.6.

#### 탄창·재장전 (2026-09-14)

원거리 무기는 **탄창 크기만큼만 연사**하고, 다 쓰면 재장전해야 이어서 쏜다. 대신 기본 연사 속도를 올려(라이플 제외) 몰아치는 구간과 끊기는 구간의 리듬을 만든다.

| 무기 | 탄창 | 발사 간격 (이전→현재) | 재장전 |
|:---|--:|:---|--:|
| 라이플 | 30 | 0.1s (유지) | 2.0s |
| 피스톨 | 12 | 0.5s → 0.4s | 1.5s |
| 샷건 | 6 | 1.5s → 1.2s | 2.5s |
| 런처 | 4 | 3.0s → 2.4s | 3.0s |

- **발사 1회 = 1발.** 산탄도 한 번 쏘면 1발이다.
- **빈 탄창으로 쏘려 하면 자동 재장전**. 수동 재장전은 `R` / 게임패드 `Y`. 가득 차 있으면 반응하지 않는다.
- **공격속도(`AttackSpeed`) 버프가 재장전 시간도 같은 배율로 줄인다.**
- **경직·무기 교체·대시로 취소되고, 취소되면 탄은 채워지지 않는다.**
- **잔량은 무기별로 기억된다.** 라이플 5발 쏘고 피스톨로 바꿨다 돌아오면 25발이다. 교체로 재장전을 건너뛸 수 없다. 드랍→재획득(다른 플레이어가 주워도)에도 유지된다.
- HUD에 `잔량 / 탄창 크기`를 표시한다. 근접 무기와 적 NPC 무기는 탄약 개념이 없다.

구현 상세는 [TechDesign_Ability.md](TechDesign_Ability.md) §5.5.

#### 무기 레벨 (2026-08-20)

레벨이 오르면 ① 무기 기초 스텟과 ② 무기 내장 어빌리티의 피해 계수가 함께 오른다.

- **레벨별 값은 공식이 아니라 무기별 DataTable에 절대값으로 입력한다** (`ULNPWeaponData::LevelTable`, 행 구조 `FLNPWeaponLevelRow`). 지수 곡선을 씨앗으로 넣고 레벨마다 손으로 조정하는 전제다. 높은 레벨에서만 새 스텟이 붙는 설계도 가능하다.
- **행 이름이 레벨 숫자("1"~"N")이고, 마지막 행이 최대 레벨이다.** 테스트 데이터는 10레벨까지.
- 최종 피해 = `AttackPower × (어빌리티 BaseDamageCoefficient × 레벨 행의 AbilityCoefScale)`.
  ⚠️ 기초 스텟과 계수가 **둘 다** 레벨로 오르므로 피해는 제곱으로 증가한다. 의도된 설계지만 `AbilityCoefScale`은 완만하게 올려야 한다.

#### 무기 합성 (Merge)

**같은 종류·같은 레벨 무기 n개 → 다음 레벨 무기 1개.** n은 `LNPSettings.WeaponMergeMaterialCount`(기본 3).

- **장착 중인 무기는 재료로 쓸 수 없다.** 대신 인벤토리 재료 n-1개로 **장착 무기를 +1레벨** 할 수 있다 — 대상 자신이 재료 1개 몫을 하는, 같은 규칙의 두 얼굴이다.
- 최대 레벨이면 합성 불가.
- 진입점은 인벤토리 디테일 패널의 **Merge 버튼**. 라벨은 대상 자신을 뺀 재료 현황이라 기본값에서는
  `Merge (보유/2)`로 보인다 (→ [TechDesign_InGameMenu.md](TechDesign_InGameMenu.md) §5.3).
- 강화한 레벨은 드랍→재획득(다른 플레이어가 주워도)에서 보존된다.

### 3.2 스킬 아이템 (Skill)

> 데이터 정의(`ULNPSkillData`)와 장비 슬롯만 있고, **발동 입력·자동 발동 연결은 미구현**이다(§6).

#### Active Skill (키 맵핑)
- 지정 키로 **직접 발동**. 슬롯 제한 있음(기본 4, Project Settings).
- 슬롯이 꽉 찬 상태에서 새로 장착하면 기존 슬롯 하나와 교체.
- 예) 순간이동, 광역 넉백, 보호막 전개

#### Passive Skill (자동 발동)
- 조건 충족 시 **자동 발동**. 슬롯 제한 없음.
- 예) 피격 시 순간 무적, 체력 30% 이하에서 이동속도 증가

### 3.3 버프 아이템 (Buff)

#### 합연산 / 곱연산 이원 구조

```
최종 스텟 = (캐릭터 기초 + 무기 스텟 + 합연산 버프) × (1 + Σ 곱연산 버프)
```

| 종류 | 성격 | 표기 | 희소성 |
|:---|:---|:---|:---|
| **곱연산 버프** | 대부분의 일반 버프. 배율끼리 **합해진 뒤 한 번** 곱해진다 | "공격력 +40%" | 일반 |
| **합연산 버프** | 기초 스텟을 직접 올린다. 모든 곱연산 버프에 **증폭**되므로 고효율 | "기초 공격력 +10" | **레어** |

- **모든 스텟에 두 종류가 다 있다.** 배율 스텟(이동·공격·루팅 속도)은 기초가 1.0이라 합연산도 퍼센트로 표기한다("기초 이동속도 +10%").
- 같은 스텟의 곱연산 버프를 중복 획득하면 배율이 **합산**되어 체감 효율이 떨어진다: +40% ×1 = 140%, ×2 = 180%(직전 대비 +28.6%), ×3 = 220%(+22.2%).
- ⚠️ 곱연산 버프는 기초값이 0인 스텟에서 무효다(0 × 1.4 = 0). 그래서 `DefensePower` 기초를 10으로 둔다.

#### 지속 시간

`Duration`이 **양수면 기간제, `-1`이면 영구**다. 영구 버프는 만료되지 않고 UI에 남은 시간도 없다. 기간제는 **플레이어가 보유하는 동안에만** 시간이 줄어든다.

| 상황 | 남은 시간 변화 |
|:---|:---|
| 인벤토리에 보유 중 | 실시간 차감 |
| 바닥에 드랍됨 | **차감 중지** |
| 다른 플레이어가 주움 | 차감 재개 |
| 0 도달 | 아이템 소멸, 스텟 효과 제거 |

> 예: 5분짜리 버프를 4분 보유 후 드랍 → 바닥에 1분짜리로 존재. 다른 플레이어가 주우면 1분 적용 후 소멸.

#### 오써링

버프 DataAsset이 `{어트리뷰트, 연산(Flat/Percent), 크기}` 목록을 선언하면 공용 GE 2종(`ULNPGameplayEffect_StatFlat` / `_StatPercent`)이 SetByCaller로 받아 적용한다. **스텟×연산 조합마다 GE 에셋을 만들지 않는다**(→ [TechDesign_Ability.md](TechDesign_Ability.md) §2.1). 아이템 설명문("공격력 +40%")도 이 선언에서 자동 생성된다.

#### 버프 아이템 목록

`PoiseResistance`를 뺀 스텟 6종 각각에 합연산·곱연산 한 쌍씩(12개). 에셋은 `/Game/ItemData/Buffs/DA_Buff_<스텟>_AddBase|MulAdd`.

| 아이템 | 대상 스텟 | 아이콘 (실루엣 / 액센트) |
|:---|:---|:---|
| Vitality Core | MaxHealth | 하트 / 레드 |
| Power Surge | AttackPower | 교차 슬래시 X / 오렌지 |
| Frenzy | AttackSpeed | 번개 / 옐로 |
| Bulwark | DefensePower | 방패 / 블루 |
| Swift Step | MoveSpeed | 이중 셰브론 » / 민트 |
| Loot Booster | LootSpeed | 루팅 게이지 링 / 퍼플 |

- 6종 모두 실제 게임플레이에 반영된다(2026-07-27 서버·클라 PIE 검증).
- `AttackSpeed` → 근접 몽타주 재생 속도(히트 윈도우 ANS도 압축) + 무기 `FireCooldown` 나눗셈 + 재장전 시간. **몽타주와 쿨다운을 같은 계수로 줄여야** 실제 공격 빈도가 계수만큼 빨라진다(한쪽만 줄이면 다른 쪽이 병목). 피격 반응·패링·경직 몽타주는 대상이 아니다.
- `MoveSpeed` → `FLNPMoveSpeedModifier`가 이동 상태 전체의 `MaxSpeed`에 곱한다(→ [TechDesign_CharacterMovement.md](TechDesign_CharacterMovement.md) §4.1).
- 아이콘은 LootDice 6면 시인성을 위해 **어두운 배경 + 굵은 흰 코어 + 스탯별 액센트 림** 규격이다. 주사위 위에서는 `CategoryColor`(버프 = 초록)가 곱해져 액센트가 사라지므로 **실루엣만으로 구분**되어야 하고, 액센트 색은 인벤토리 UI 구분용이다(→ [TechDesign_LootDice.md](TechDesign_LootDice.md) §2.2).

## 4. 인벤토리 구조

어빌리티 셋과 아이템은 모두 **PlayerState에 귀속**된다. 폰이 교체되는 상황(사망 리스폰, 기간제 폰 아이템 등)에도 스킬·버프 효과가 유지되어야 하기 때문이다.

### 4.1 PlayerState 귀속

| 저장소 | 내용 | 개수 |
|:---|:---|:---|
| 무기 슬롯 | 현재 장착 무기 | 1 |
| Active Skill 슬롯 | 키 맵핑 스킬 | N개 (설정값) |
| Passive Skill 목록 | 자동 발동 스킬 | 무제한 |
| 버프 아이템 목록 | 스텟 버프 | 무제한 |
| 아이템 보관함 | 미장착 아이템 | 무제한 |

> 버프 아이템과 Passive Skill은 장착 개념 없이 보유만으로 활성화된다.

구현 구조는 [TechDesign_Inventory.md](TechDesign_Inventory.md).

## 5. 스텟 시스템

스텟 하나당 어트리뷰트 하나다. 배율용 보조 어트리뷰트를 따로 두지 않고, 합/곱은 같은 어트리뷰트의 서로 다른 연산 채널로 들어간다(§3.3).

| 스텟 | 설명 | 플레이어 기초값 | 표기 |
|:---|:---|:---|:---|
| Health / MaxHealth | 현재/최대 체력 | 100 | 정수 |
| AttackPower | 기본 공격·어빌리티 피해량 | 10 | 수치 |
| AttackSpeed | 공격 속도 배율 (몽타주 속도·쿨다운·재장전 연동) | 1.0 | 퍼센트 |
| DefensePower | 피해 감소 `100/(100+Def)` | 10 | 수치 |
| MoveSpeed | 이동 속도 배율 | 1.0 | 퍼센트 |
| LootSpeed | LootPod 루팅 게이지 진행 속도 배율 | 1.0 | 퍼센트 |
| PoiseResistance | 경직력 감쇠 `100/(100+Res)` (→ [GameDesign_Poise.md](GameDesign_Poise.md)) | 150 (적은 20) | 수치 |

- **무기 스텟도 이 어트리뷰트에 합산된다.** 무기가 버프와 같은 형식으로 `{AttackPower, Flat, N}`을 선언하고 장착 중에만 GE로 적용된다. 그래서 곱연산 버프가 무기 공격력까지 증폭한다.
- 탄창 잔량·크기도 어트리뷰트지만 스텟이 아니라 상태라 이 표·버프·스탯 탭 대상이 아니다.

### 캐릭터 스텟 UI 표기

`C (A × B)` — **A** = 기초 총량(캐릭터 기본 + 무기 + 합연산 버프), **B** = 곱연산 버프 총 배율(버프 없음 = 100%), **C** = 최종값.

```
HP              62 / 150
Max HP          150 (100 × 150%)
Attack          66.0 (55.0 × 120%)
Attack Speed    154% (110% × 140%)
Defense         28.0 (20.0 × 140%)
Move Speed      154% (110% × 140%)
Loot Speed      140% (100% × 140%)
```

## 6. 구현 현황

### 완료된 기능

| 기능 | 세부 내용 |
|:---|:---|
| ASC (PlayerState) | `ALNPPlayerState`에 귀속. 폰 교체에도 어빌리티·버프 유지 |
| AttributeSet | 스텟 7종 + `MagazineAmmo`/`MagazineSize`(상태) + `IncomingDamage`(Meta). 플레이어 기초값은 `DT_PlayerBaseStats`로 초기화 |
| 합/곱 스탯 파이프라인 | 선언형 `FLNPStatModifier` + 공용 GE 2종. 무기·버프가 같은 형식 |
| 아이템 DataAsset | Weapon / Skill / Buff 분리. 무기 레벨 테이블·합성 |
| 장비·인벤토리 | 무기 슬롯 1 + Active Skill 슬롯 N + Passive 목록, 가방·버프 인스턴스 복제. LootDice 픽업 시 인벤토리에 추가 |
| 원거리 기본 공격 | Mass Entity 발사체 스폰 후 즉시 종료. 산탄(육각 링 19발)·곡사(Lobbed) 포함. 트레일 진영 색 |
| 근접 기본 공격 | Chooser 몽타주 + 콤보 섹션, Swept Volume 판정, 타겟 보정 |
| 공격 쿨타임 | 단일 쿨다운 GE에 무기별 `FireCooldown` 주입, **무기별로 각자 돈다** |
| 탄창·재장전 | 무기별 탄창·재장전 시간, 자동 재장전, 경직·교체·대시 취소, 무기별 잔량 유지, HUD 표시 |
| 경직 리액션 | 경직도 상태 전이로 그로기·다운 GA 발동(→ [GameDesign_Poise.md](GameDesign_Poise.md)) |
| 공격 입력 | 공격 버튼 → 장착 무기 GA 발동. 쿨타임 중 입력 0.05초 버퍼 |

### 미구현 항목

| 기능 | 세부 내용 |
|:---|:---|
| Active Skill 입력 → 발동 | 입력 액션 배열(`ActiveSkillActions`)은 바인딩돼 있으나 슬롯 GA 발동 연결 없음 |
| Passive Skill 자동 발동 | 피격 등 조건 이벤트를 피격자 ASC로 보내 Passive GA를 트리거하는 흐름 없음 |
| 무기 추가 어빌리티 | 기본 공격 외 GA(차지 공격 등) 없음 |
| Pistol·Rifle 트레일 진영 색 | 해당 트레일 Niagara 시스템에 `TintColor` 파라미터 추가 필요 (→ [TechDesign_Ability.md](TechDesign_Ability.md) §3.2) |
