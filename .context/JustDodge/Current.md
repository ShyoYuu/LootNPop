# 저스트 회피 현재 작업 상태

> 상태: 활성 인계 문서
> 현재 작업: V4a 주요 검증·세션 마감 — CVar 보존, 기본값 0 반영·최종 빌드 통과
> 마지막 갱신: 2026-11-06

## 현재 결정

사용자가 정한 것:

- 저스트 회피는 근접 공격과 투사체 직격에만 발동한다(J-002).
- 무적 중인 플레이어를 지나는 투사체는 관통한다(J-003). 단, 피격 유예로 소급 회피된 탄은 관통하지 않는다(J-019).
- 반경은 기존 패링 반경을 쓴다(J-004).
- 버프는 AttackSpeed·MoveSpeed 곱연산 +20%, 2.5초, 시간만 갱신한다(J-005). 사용자가 천천히 상향을 검토한다.
- 연출은 서버 확정 뒤에만 낸다(J-007).
- 화상 지속 틱은 무적으로 막지 않는다(J-013). PvP 근접 예측 HitStop 어긋남은 허용한다(J-014).
- 원격 게스트 피격 효과는 피격 유예 버퍼로 보류하고, 늦게 도착한 대시가 소급 회피한다(J-015~J-019, J-010 대체).
- 비주얼은 메인 트랙 뒤의 독립 트랙으로 둔다(J-012). 그래픽스와 무관한 1차(V1a·V2·V3a·V4a)는 그래픽스 Phase 0보다 먼저 하고, 2차(V3b·V5·V6·V4b)는 그래픽스 게이트 뒤에 한다(J-020).
- 사용자 시각 평가 뒤 보라색 초안을 폐기했다. 검정 중심의 무채색·약한 흰색 중심 강조(J-021), 전신 속도선과 플래시 제거 또는 완만한 페이드(J-022)를 적용한다.

- 원격 플레이어 Ghost 착탄은 탄별 탄속으로 가른다(J-027, J-026 대체). 기준 이상은 로컬 예측, 미만은 서버 착탄 큐를 기다린다. 소멸한 Ghost의 복구는 만들지 않는다. 원격 미러/진단 정리는 별도 논의한다.

## 이번 세션 마감 상태

- **V4a 주요 검증 마감:** 순보·잔상·카메라·오라를 합친 지연 체감이 자연스럽다는 사용자 평가로 J-007을 유지한다. 실제 CVar 0에서 PktLag 0·양쪽 50 모두 저스트 회피 성공 탄의 소멸을 보지 못했고 일반 명중 지연도 거의 느껴지지 않는다고 확인했다. [V4a 실행서](phases/PhaseV4a_VisualReadability.md), [기록](history/PhaseV4a_Log.md).
- **현재 기본값:** `LNP.Projectile.RemoteImpactPredictMinSpeed 3000`(J-027). 현재 NPC 탄 1000 cm/s는 서버 착탄 큐를 기다려 V4a A/B의 값 0과 같게 동작한다. 기준 이상인 탄은 로컬 예측이며 J-025 원격 무적 미러를 사용한다. 값 0은 항상 예측, 충분히 큰 값은 항상 대기다. 로컬 플레이어·적·지형/수명 처리·서버 피해 판정은 유지한다. 원격 미러·전용 테스트·임시 명령·진단 로그는 삭제하지 않았다.
- **착탄 키 수정:** CVar 0 비교에서 드러난 기존 Iris 전달 누락을 식별자 3개의 UPROPERTY 선언으로 수정했다. 이전 서버 음수 key가 게스트 key=0으로 도착하던 문제가 해소됐고, 일반 명중 Ghost 소멸을 사용자가 확인했다. 잘못된 네트워킹 문서 설명도 정정했다.
- **최종 빌드:** `LootNPopEditor Win64 Development -WaitMutex -NoHotReloadFromIDE -DisableAdaptiveUnity` 통과. 기본값 변경의 컴파일 뒤 에디터 DLL 잠금으로 링크가 한 번 실패했으며, 사용자 저장·종료 확인 후 남은 2개 작업·2.84초에 링크/메타데이터가 성공했다. 다른 작업 문서·사용자 에셋 변경이 있는 트리라 깨끗한 트리 빌드로 기록하지 않는다.
- **기존 검증:** 원격 무적 시간·서버 보정·직렬화/복사 자동화 1건 통과, 원격 미러 정규 빌드 42.82초, 착탄 키 수정 UHT 포함 정규 빌드 75.40초 통과. 값 0 사용자 A/B는 그 빌드로 확인했다. 마지막 변경은 기본값·도움말뿐이라 같은 플레이 검증을 다시 요청하지 않았다.

## 설정과 검증 범위

- 대시 무적 0.15초·저스트 창 0.12초, 버프 2.5초·AttackSpeed/MoveSpeed +20%, 서버 피격 유예 설정은 유지한다. 메인 트랙 설계는 [TechDesign_JustDodge.md](../TechDesign_JustDodge.md)가 소유한다.
- 양쪽 `net.PktLag=50`은 편도 각각 약 +50ms, 추가 RTT 약 +100ms다. 이번 로그의 RTT는 설정 후 106~158ms로 기록됐으며 RTT 200ms 검증으로 확대하지 않는다. 종료 전 PktLag 0 명시적 복원은 별도 확인하지 않았고 사용자는 마지막 빌드 전에 에디터를 종료했다.
- 사용자 적 에셋 설정은 링 1→0(7발→1발)·반경 15→60이다. 세 순수 엔티티 적 에셋에서 확인했으며 에이전트는 이를 수정하지 않았다. 호스트 본인 화면에서도 난도가 비슷했고 사용자는 산탄 수 감소의 영향이라는 설명에 동의했다.
- 값 0 구간의 서버 성공은 지연 0에서 18건, 양쪽 50에서 11건이다. 두 구간 모두 키 0 누락·소급 성공은 없다. 관통의 자연스러움은 사용자 관찰이며 개별 성공 탄 전체 생존 경로나 성공률을 자동 측정한 것은 아니다.
- V1a 부재 중 무기 교체·사망, V2 잔상 수명 중 정확한 피격·넉백, V3a ADS 전환의 정확한 경계·명시적 resume 콘솔, 보정 빈도 비교, 공통 회귀 전체·깨끗한 트리 빌드는 기존 미확인 범위를 유지한다. [V1a](phases/PhaseV1a_Blink.md), [V2](phases/PhaseV2_Afterimage.md), [V3a](phases/PhaseV3a_CameraAura.md) 참고.

## 재검증 메모

- 미리보기 `LNP.Debug.JustDodgePreview`는 기본 0이다. 실제 성공·원격 관찰·지연 검증은 0으로 한다. `LNP.Debug.JustDodgeTest`는 공격 접촉이나 누름부터 큐까지의 지연 검증을 대신하지 않는다. 사용법은 [Validation.md §5](design/Validation.md).
- 착탄 진단은 `LNP.Debug.Dodge 1`: Send와 Receive net=3의 player/key/index를 대조한다. net=2의 destroyed=0은 호스트에 Ghost가 없어서 정상이고, 게스트의 0도 이미 로컬 소멸·미스폰일 수 있다.
- PvP 검증은 PIE마다 `LNP.Team.Set 1 2`를 다시 입력한다. 지연 에뮬레이션도 각 창의 송신에 적용하므로 두 창에 넣고 종료 때 0으로 복원한다. 기타 로그 규약·기존 분석 스크립트는 [Validation.md](design/Validation.md)를 따른다.
