# 저스트 회피 현재 작업 상태

> 상태: 활성 인계 문서
> 현재 작업: V3a 구현·주요 검증 마감 — V4a는 새 세션으로 인계
> 마지막 갱신: 2026-11-06

## 현재 결정

사용자가 정한 것:

- 저스트 회피는 근접 공격과 투사체 직격에만 발동한다(J-002).
- 무적 중인 플레이어를 지나는 투사체는 관통한다(J-003). 단, 피격 유예로 소급 회피된 탄은 관통하지 않는다(J-019).
- 반경은 기존 패링 반경을 쓴다(J-004).
- 버프는 AttackSpeed·MoveSpeed 곱연산 +20%, 2.5초, 시간만 갱신한다(J-005). 사용자가 천천히 상향을 검토한다.
- 연출은 서버 확정 뒤에만 낸다(J-007).
- 화상 지속 틱은 무적으로 막지 않는다(J-013). PvP 근접 예측 HitStop 어긋남은 허용한다(J-014).
- 원격 게스트 피격 효과는 피격 유예 버퍼로 보류하고, 늦게 도착한 대시가 소급 회피한다(J-015~J-019, J-010 대체).
- 비주얼은 메인 트랙 뒤의 독립 트랙으로 둔다(J-012). 그래픽스와 무관한 1차(V1a·V2·V3a·V4a)는 그래픽스 Phase 0보다 먼저 하고, 2차(V3b·V5·V6·V4b)는 그래픽스 게이트 뒤에 한다(J-020).
- 사용자 시각 평가 뒤 보라색 초안을 폐기했다. 검정 중심의 무채색·약한 흰색 중심 강조(J-021), 전신 속도선과 플래시 제거 또는 완만한 페이드(J-022)를 적용한다.

## 메인 트랙이 남긴 토대

- 판정: `ExecuteDash`가 무적·저스트 창을 `FLNPParryStateFragment`에 기록한다(원격 게스트는 `E − U`부터). `Judge` 순서는 Parried → JustDodged → (반경 밖 None) → Dodged → Guarded → Hit이다. 성공은 `FLNPJustDodgeCommand`가 버프 GE와 `.Success` 큐로 처리한다.
- 수치: Mover 컴포넌트의 `IFrameDuration` 0.15·`JustDodgeWindow` 0.12. 프로젝트 설정 `Combat|Just Dodge`는 버프 2.5초·0.2·0.2와 피격 유예 `HitGraceInputAllowance` 0.045·`HitGraceJitterMargin` 0.04·`HitGraceMax` 0.25다.
- 연출 경계: 큐 태그 `GameplayCue.LNP.JustDodge.Success`·`.Buff`. 성공 큐 에셋의 부모는 `ULNPGameplayCueNotify_JustDodgeSuccess`다. V1a가 이 클래스에 순보를 붙인다. 소유 화면의 누름 → 큐 지연은 RTT +100에서 p50 약 150ms, PktLag 50(두 창)에서 약 225ms다. V-05에서 다시 본다.
- 프로젝트 공통 문서: [GameDesign_JustDodge.md](../GameDesign_JustDodge.md), [TechDesign_JustDodge.md](../TechDesign_JustDodge.md).

## 바로 다음 행동

- **V3a 주요 검증 마감:** 카메라 체감·오라 외형·어두운 곳 시인성, 실제 성공 2인 양방향 오라·본인만 카메라 효과, 버프 갱신 유지·소멸을 사용자가 확인했다. 버프 중 콘솔 사망·리스폰 뒤에도 이상 없었다. 정규 unity 빌드·BP/머티리얼/Niagara 검증·저장 통과, 현행 수치를 유지한다. ADS 전환의 정확한 경계와 명시적 resume 콘솔은 별도 런타임 미확인이다. [V3a 실행서](phases/PhaseV3a_CameraAura.md), [기록](history/PhaseV3a_Log.md).
- **새 세션 V4a:** 사용자가 이번 세션은 인계 문서와 함께 한 커밋으로 마감하고 V4a는 새 세션에서 진행하도록 정했다. V4a는 미착수이며 실행서도 아직 없다. 다음 세션은 아래 절차로 지연 중 순보 판독(V-05)과 J-007 유지 여부를 확인한다. 임시 명령·미리보기는 유지하되 지연 체감은 반드시 미리보기 0의 실제 성공으로 검증한다.
- **V2 주요 검증:** 사용자가 여러 무기 교체가 잔상에 잘 반영되고, 호스트·게스트에서 상대 잔상이 잘 보이는 것을 확인했다. 난전 속에서도 잔상이 안정적으로 유지됐다고 보고했다. 잔상 수명 중 피격·넉백 순간은 확신하지 못했으므로 해당 경계는 런타임 미확인으로 남긴다. 몸·무기 컴포넌트 재사용·미부착·Tick 없음, 0.35초 머티리얼 페이드의 현행 구현과 수치를 유지한다. 밝기·시간의 별도 선호 평가는 보고받지 않았다. [V2 실행서](phases/PhaseV2_Afterimage.md), [작업 기록](history/PhaseV2_Log.md)
- **V2 빌드·연결:** UHT·전체 unity 빌드 12개 작업 성공(103.62초), 성공 큐 `AfterimageMaterial` 연결·BP 및 머티리얼 컴파일·대상 두 에셋 저장을 확인했다. 로그에는 미리보기 1→0 전환이 남았고, 판정 디버그가 꺼져 있어 이번 실제 성공 건수는 집계하지 않았다. 양방향 출력은 사용자 관찰 근거다.
- **V1a 주요 검증 마감:** 양방향 성공 이펙트·일반 대시 미재생·가드/패링/피격/넉백 회귀를 사용자가 확인했다. 최초 2인 검증 로그는 서버 성공 30건·양쪽 큐 60건이다. 게스트 속도선 방향 불일치는 실제 `DashDirection`을 창과 함께 미러하고 성공 큐로 전달하도록 수정했으며, 전체 빌드와 사용자 재검증을 통과했다. 현행 색·크기·입자 수·숨김 0.12초를 유지한다. 상세는 [V1a 실행서](phases/PhaseV1a_Blink.md)와 [로그](history/PhaseV1a_Log.md)에 있다.
- **잔여 검증:** V1a 부재 0.12초 중 무기 교체·사망, V2 잔상 수명 중 정확한 피격·넉백 경계는 런타임 미확인이다. 여러 행동에서 보정 캡슐이 빈번하지만 체감 위치 튐은 없었다. 순보 전후 보정 빈도·크기 비교는 미측정이며 전반적인 Mover 보정은 별도 조사 항목이다. `-DisableAdaptiveUnity` 전체 빌드는 통과했지만 다른 문서 변경이 있는 트리였으므로 깨끗한 트리 빌드로 기록하지 않는다.
- **미리보기 유지:** `LNP.Debug.JustDodgePreview 1`은 로컬 대시마다 비주얼만 재생한다. 기본값은 0이며 실제 성공·원격 관찰·큐 지연 검증은 반드시 0에서 한다. 미리보기와 정식 경로의 차이가 이번 방향 결함을 가렸으므로 후속 단위도 실제 성공을 함께 검증한다. 사용법과 제거 위치는 [Validation.md §5](design/Validation.md)에 있다.
- **1차 제약과 다음 순서:** V1a → V2 → V3a → V4a. Niagara는 로컬 스페이스 버스트, 캐릭터 오버레이·임시 화면 효과는 쓰지 않는다. ADS 중 FOV 펀치 생략·진입 시 종료는 J-024로 확정했다. 2차(V3b·V5·V6·V4b)는 [Graphics/Current.md](../Graphics/Current.md)의 해당 게이트를 확인한 뒤 시작한다.

## 다음 세션 시작 절차

1. `README.md`·이 문서·`Decisions.md`를 읽고, `design/VisualDesign.md` §2.1·§2.5와 `design/Validation.md` §5의 V-05·임시 명령을 확인한다. V3a 현행 수치와 미확인 경계는 [실행서](phases/PhaseV3a_CameraAura.md)에 있다. 소스·대상 에셋 상태를 확인하고 V4a 실행서를 착수 시 작성한다.
2. TestMap03 리슨 2인에서 양쪽 `LNP.Debug.JustDodgePreview 0`·`net.PktLag=0`으로 기준 체감을 확인한 뒤, 양쪽 `net.PktLag=50`(RTT 약 +100ms)에서 실제 성공을 관찰한다. 필요하면 양쪽 100도 추가한다. 본인 화면에서 순보가 회피로 읽히는지 사용자의 수동 평가를 먼저 받고, 별도 측정 장치를 먼저 만들지 않는다. 종료 뒤 양쪽 PktLag를 0으로 복원한다.
3. 늦게 도착한 큐가 ADS 중이면 FOV 펀치가 생략되는지 등 미확인 경계도 가능한 범위에서 함께 본다. `LNP.Debug.JustDodgeTest`는 공격 판정·누름부터 큐까지의 지연 검증을 대신하지 않는다. 연출 예측이 필요하다고 판단돼도 먼저 사용자와 J-007을 재논의하고, 바로 예측 코드를 넣지 않는다.
4. V4a 결과 정리 뒤 다음 구현 단위 진행 여부를 다시 확인한다. V3b 이동 꼬리·V5 화면 효과·V6 림라이트는 해당 그래픽스 게이트 전까지 추가하지 않는다.

## 인계 근거

- 검증 절차와 로그 문자열: `design/Validation.md`. PvP 경로는 `LNP.Team.Set 1 2`를 빼먹지 않는다(§6). PIE를 새로 시작하면 다시 넣어야 한다.
- 지연 에뮬레이션: `net.PktLag=N`은 입력한 창의 송신에만 걸린다. 호스트·게스트 두 창 모두에 넣어야 RTT가 약 +2N이 된다.
- 단일 프로세스 PIE 로그에서는 폰 이름이 월드마다 다르거나 겹친다. 집계 스크립트는 시각과 역할로 짝짓는다.
- 지연 중 게스트 리스폰 때 Iris `Rejected RPC (0:0) ... missing object` 에러가 2~4줄 난다. 서버가 파괴된 옛 폰으로 날아오던 게스트 이동 입력 RPC를 버리는 것이다. 영향이 없고 피격 유예와도 무관하다(`history/Phase04_Log.md` 2026-11-05).
- 빌드·PIE 검증 방법: 프로젝트 공통 워크플로를 따른다. 커밋한 뒤에는 `-DisableAdaptiveUnity`로 전체 unity 구성을 한 번 확인한다(adaptive unity가 수정 중인 파일을 unity에서 빼기 때문이다).
