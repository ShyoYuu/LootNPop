# 저스트 회피 로드맵

> 상태: 기준 로드맵
> 읽기 조건: Phase 전환, 전체 순서 변경, 범위 재산정, 그래픽스 이관 항목 확인 시
> 마지막 갱신: 2026-10-26

## 1. 진행 원칙

- **메인 트랙(게임플레이)은 비주얼 없이 완결한다.** 성공 여부는 디버그 화면 텍스트로 확인한다.
- **비주얼 트랙(V)은 맨 마지막에 독립적으로 진행한다(J-012).** 메인 트랙 Phase 2의 연출 경계(큐 태그 2개 + 빈 GCN 에셋)만 있으면 시작할 수 있다.
- 각 Phase는 따로 검증하고 커밋할 수 있어야 한다.
- 다음 Phase의 상세 실행서는 착수 직전에 쓴다.
- 모든 Phase의 완료 조건에 다음 두 가지를 넣는다.
  - `design/Validation.md` §2 공통 회귀(가드·패링, 일반 피격, 대시 이동·대시 점프, 2인 보정 캡슐)
  - 깨끗한 트리에서 Build.bat 통과

## 2. 단계 의존성

`Phase 1 회피 무적`
→ `Phase 2 저스트 회피 판정 + 버프 + 연출 경계`
→ `Phase 3 수치 1차 튜닝·지연 측정·문서 마감`

`비주얼 트랙 V`는 Phase 2 뒤라면 언제든 시작할 수 있다. 다만 사용자 계획상 맨 마지막에 두고, 그래픽스 작업(GPU 프로파일링, 커스텀 렌더 패스, 군중 렌더링)이 진행된 뒤 이관 항목(§4)의 경계를 다시 확인한다.

## 4. Phase별 범위 보충

### Phase 1

이 Phase의 위험은 크게 두 가지다.

- **누락 경로:** `Judge`를 거치지 않고 플레이어에게 피해를 주는 경로가 있으면, 그 경로에서는 무적이 새어 나간다.
- **투사체 재피격:** 무적이 끝난 직후 같은 탄이 다시 맞는 경우다.

그래서 단위 0에서 피해 경로를 전수 조사한다. 상세는 Phase 문서가 소유한다.

### Phase 2

- 프래그먼트에 저스트 창 만료 시각과 소비 플래그를 추가하고, `Judge`에 `JustDodged`를 추가한다(`design/Architecture.md` §3).
- 투사체 직격 경로는 지금 `PS.bIsParrying`일 때만 패링 반경을 계산한다. 저스트 창이 열려 있을 때도 계산하도록 조건을 넓힌다.
- 성공 커맨드 `FLNPJustDodgeCommand`와 버프 GE `ULNPGameplayEffect_JustDodgeBuff`를 만든다(§5).
- **연출 경계:** 태그 `GameplayCue.LNP.JustDodge.Success`·`GameplayCue.LNP.JustDodge.Buff`를 정의하고 빈 GCN 에셋을 연결한다. 이 Phase에서는 비주얼을 만들지 않는다.
- `LNP.Debug.Dodge 1`일 때 성공 화면 텍스트를 띄운다(테스터 피드백용).
- 확인할 위험: MoveSpeed는 ASC에서 직접 읽기 때문에 버프가 켜지고 꺼지는 순간 보정이 생길 수 있다([CharacterMovement §4.1](../TechDesign_CharacterMovement.md)). 2인 PIE에서 `mover.debug.ShowCorrections 1`로 확인한다.

### Phase 3

- 사용자 플레이 테스트로 `IFrameDuration`·`JustDodgeWindow`·버프 수치를 1차로 확정한다. 군중(대부분 순수 엔티티)에 둘러싸인 상황에서 저스트 회피가 지나치게 쉬운지도 본다.
- 네트워크 에뮬레이션(`PktLag` 50/100ms)으로 게스트가 대시했을 때 판정 성공률과 체감을 기록한다. 결과에 따라 J-007(연출 예측 없음)과 J-010(RTT 역보정 없음)을 재검토한다. 대응 후보는 `design/Architecture.md` §6에 있다.
- 공통 문서를 마감한다.
  - `GameDesign_JustDodge.md`·`TechDesign_JustDodge.md`를 새로 만든다.
  - `TechDesign_ParrySystem.md`(Judge 순서), `TechDesign_HitDetection.md` §7.5(결과 enum), `TechDesign_CharacterMovement.md` §5(대시 무적)에 교차 링크를 넣는다.
  - 문서 인덱스 3곳(CLAUDE.md, ProjectOverview, Notion)과 `DevelopmentPlan.md`를 갱신한다.

### 비주얼 트랙(V)

- V를 시작하기 전에 그래픽스 작업의 진행 상황을 확인한다. 특히 다음 두 가지를 본다.
  - 화면 효과 레이어가 생겼는가
  - Niagara 원거리 정밀도 문제의 원인이 확정됐는가
- 설계 원본은 `design/VisualDesign.md`다.

## 5. 그래픽스 작업으로 넘기는 항목 (J-012)

이 표가 이관 항목의 원본이다. 그래픽스 작업 폴더가 생기면 그쪽에서 이 표를 가져가고, 여기에는 링크만 남긴다.

| 항목 | 넘기는 이유 | 저스트 회피 쪽에 남는 것 |
|:---|:---|:---|
| 로컬 화면 연출(채도 감소·색수차·방사형 블러) | 스캔 시야·구면 포그와 같은 풀스크린 패스 계층이다. 피격·저체력·스캔 시야와 함께 "화면 효과 레이어"(우선순위·블렌드 가중치)를 한 번에 설계하는 편이 낫다 | 트리거만 제공한다: 소유 클라이언트의 성공 이벤트 + 강도 커브. 연출 의도는 `design/VisualDesign.md` §2.3 |
| 버프 오라의 림라이트(OverlayMaterial) | 스캔 시야의 적·아군 강조가 CustomDepth/스텐실이나 오버레이를 쓸 가능성이 높다. 캐릭터 강조 채널은 한 곳에서 설계해야 충돌하지 않는다 | 버프 지속 큐(`.Buff`)의 On/Off 시점과 파티클 부분(V3) |
| 원점에서 먼 Niagara 정밀도 문제 | [TechDesign_ParrySystem.md](../TechDesign_ParrySystem.md) §8에 "원인 미확정"으로 남아 있다. 렌더링·LWC 정밀도 조사 주제다 | 원인이 확정되면 V1·V2 이미터 규칙(로컬/월드 스페이스, 힘 모듈)을 그 결론에 맞춘다 |
| 잔상 반투명 비용 측정 | GPU 프로파일링 하네스에서 함께 잰다 | 잔상 구현 자체(V2) |

## 6. 범위 밖과 후속 아이디어

- 사운드: 사운드 에셋이 생기면 성공 큐의 `Sound` 필드에 연결한다.
- 버프 남은 시간 HUD 표시: 오라로 충분한지 V4에서 판단한다.
- 적의 회피: 적이 판정 대상이 되려면 StateTree/GA에서 프래그먼트를 갱신하는 연결이 필요하다(패링과 같은 제약).
- 공중 대시: 의도된 제한이다.
- 저스트 회피 직후의 전용 반격 기술: 버프 외 보상을 추가하는 아이디어. 채택 전이면 `Idea_Backlog.md`로 보낸다.
