# 저스트 회피 비주얼 설계

> 상태: V1a·V2·V3a 주요 검증 정리, 미확인 경계는 각 실행서에 명시, V4a 이후는 계획. 비주얼 트랙(V)이 이 문서를 소유한다.
> 마지막 갱신: 2026-11-06
> 착수 조건: 메인 트랙 Phase 2의 연출 경계(큐 태그 2개 + 빈 GCN)가 있어야 한다. 1차 단위(V1a·V2·V3a·V4a)는 바로 시작한다. 2차 단위는 그래픽스 게이트를 확인한다(§3, J-020).

## 1. 원칙

- **"피했다"는 사실이 그림 하나로 읽혀야 한다.** 가드(막았다), 패링(튕겨냈다)과 다른 동사다. 핵심은 "그 자리에 없었다"다.
- **보는 사람에 따라 나눈다.**
  - 모든 플레이어가 보는 것: 성공 신호(순보·잔상)와 버프 상태(오라)
  - 본인만 보는 것: 화면 연출
- **월드 시간을 건드리지 않는다(J-008).** 서버 시간을 모두가 공유하므로 월드 슬로모는 다른 플레이어의 게임을 멈춘다.
- **색 규약(J-021):** 검정 중심의 무채색과 가운데의 약한 흰색 하이라이트를 쓴다. 낮은 시인성을 허용한다. 보라색 초안(J-009)은 사용자 시각 평가 뒤 폐기했다.

| 상황 | 색 | 근거 |
|:---|:---|:---|
| 가드 | 주황 (520,170,40) | [TechDesign_ParrySystem.md](../../TechDesign_ParrySystem.md) §8 |
| 패링 | 청백 (500,620,900) | 같음 |
| 버프 주사위 | 초록 (`CategoryColor`) | [GameDesign_Ability.md](../../GameDesign_Ability.md) §3 |
| **저스트 회피** | **검정·짙은 회색 + 흰색 중심 강조** | J-021. V1a 시각 평가와 양방향 관찰 뒤 몸체 `(0.006,0.006,0.006,0.92)`, 가는 강조선 `(18,18,18,0.70)`을 현행 값으로 유지 |

## 2. 요소별 설계

### 2.1 순보(瞬步) — 사라졌다 나타나기 [V1a, 핵심 / 오버레이 필요성은 V6에서 재검토]

사용자 아이디어다. 닌자가 사라지고 나타날 때처럼 빠르게 "슈슉" 하는 느낌을 낸다. 잔상(§2.2)과 한 동작으로 이어진다.

| 순서 | 연출 | 길이(현행) |
|:---|:---|:---|
| ① 사라짐 | 현재 위치에 잔상을 남긴다(V2). 대시 방향의 검은 속도선이 전신을 감싸고, 가운데에 가는 흰색 강조선이 섞인다 | 즉시 |
| ② 부재 | 캐릭터 메시와 무기 메시를 숨긴다(그림자 포함) | 0.12초 |
| ③ 나타남 | 전신 범위의 검은 속도선과 가운데의 가는 흰색 강조선이 대시 축에 평행하게 흐르며 부드럽게 나타났다 사라진다. 원형 플래시는 쓰지 않는다(J-022) | 입자 0.12~0.18초 |

- 구현 수단: 성공 큐(`GameplayCue.LNP.JustDodge.Success`)의 커스텀 GCN이 `ALNPCharacterBase::ApplyJustDodgeBlink`를 부른다. 캐릭터의 타이머가 0.12초 뒤 `FinishJustDodgeBlink`로 숨김·숨은 그림자 상태를 복원한다. 재진입은 첫 상태를 보존하고 타이머만 갱신한다. `bVisible`은 변경하지 않아 부재 중 무기 교체·맨손 전환을 보존하고, `AnimSourceMesh`의 상시 숨김도 유지한다. 랙돌 진입·EndPlay에서는 타이머를 정리하며 즉시 복원한다. 큐 안에는 실행별 상태를 두지 않는다.
- 숨김 0.12초는 성공 큐 도착부터 재는 연출 시간이다. 대시 시작 기준의 저스트 창 0.12초·무적 창 0.15초와 독립이며, 저스트 창과 현재 수치가 같은 것은 연동을 뜻하지 않는다. 숨김이나 복원으로 판정 창을 바꾸지 않는다. 임시 미리보기는 대시 시작 즉시 성공 큐를 재생하므로 정식 성공 연출과 시작 시점이 다르다.
- 버스트 에셋: `/Game/Effects/Combat/NS_JustDodge_Disappear`·`NS_JustDodge_Reappear`를 성공 큐의 `DisappearVFX`·`ReappearVFX`에 지정한다. 사라짐은 각 머신의 현재 캐릭터 위치와 접평면 대시 방향, 나타남은 복원 순간의 현재 위치를 사용한다. 타이머가 성공 큐의 대시 방향을 보존하고 복원 위치의 접평면에 다시 투영하므로, 옆·뒤 대시에서도 나타남이 같은 대시 축을 따른다. 두 시스템은 메시와 독립적으로 위치에 생성하며 `AutoRelease` 풀로 반환한다. 사망·EndPlay 취소에서는 나타남을 재생하지 않는다. 부모의 범용 `VFX`는 비워 중복 재생을 막는다.
- 모든 머신에서 재생된다(큐가 전파되므로).
- 방향 원본은 `ExecuteDash`가 실제 대시 무브에 사용한 `DashDirection`이다. 이를 회피 프래그먼트의 `DodgeDirection`에 소급 판정 호출 전 기록하고 성공 큐의 `Normal`에 싣는다. 성공 시점의 Actor 속도로 다시 추정하지 않는다. 게스트 소급 성공은 이동 적용 전에 실행될 수 있어 직전 이동이나 영벡터를 읽었던 방향 버그를 막는다. 수정 빌드 뒤 사용자가 실제 성공 재검증에서 방향이 잘 맞는다고 확인했다(2026-11-05).
- **지연:** 소유 화면에는 큐가 약 RTT 뒤에 도착한다(Architecture §6). 대시가 이미 끝난 뒤라면 사라짐과 나타남이 같은 자리에서 일어날 수 있다. V4a 사용자 평가(2026-11-06)에서는 PktLag 50에서도 대시 모션과 함께 잘 보이며, 눈에 보이는 효과만으로 0과 구분하기 어려울 만큼 자연스럽다고 확인했다. 이 범위에서 J-007(서버 확정 연출)을 유지한다. [V4a 실행서](../phases/PhaseV4a_VisualReadability.md).
- ⚠️ 메시를 숨기면 대시 몽타주도 함께 안 보인다. 의도된 동작이다.
- 전신 범위: 캐릭터 Up을 따르는 높이 약 187cm의 타원체 표면에 몸체 속도선을 분포시킨다. 검정은 Additive에서 보이지 않으므로 기존 반투명 `M_LNP_Smoke`를 재사용하고, 가운데의 흰색 강조선만 `M_LNP_Spark`를 쓴다. 몸체와 강조선 모두 크기·알파 곡선을 사용한다. 이전 `Flash` 이미터는 가는 강조선으로 재구성했으며 둥근 플래시는 없다. V6에서 오버레이가 필요한지도 이 사용자 피드백을 기준으로 다시 평가한다.
- 방향과 대비: 사용자 평가에서 방사형 수렴이 가시처럼 보였으므로 제거했다. 네 이미터 모두 로컬 +X, 콘 각도 0도, 650cm/s로 평행 이동하며 렌더러는 `VelocityAligned`다. 흰색 중심선은 6개·5×90~7×150cm이고, 몸체보다 나중에 그리도록 `SortOrderHint=1`을 사용한다(몸체 0). V1a 시각 평가와 양방향 관찰 뒤 현재 값을 유지한다. 잔상·오라를 합친 체감 튜닝은 V4a에서 다시 본다.

### 2.2 대시 잔상 [V2]

- 사라진 위치에 포즈 스냅샷을 남긴다. 사용자 성능 검토 뒤 1회용 액터 초안을 폐기하고 캐릭터 소유 `UPoseableMeshComponent`를 재사용하기로 했다(J-023). 몸용 하나·표시 무기용 하나를 첫 사용 때만 만들며 맨손이면 무기 잔상은 숨긴다. 원본을 순보로 숨기기 전에 `VisualMesh`와 `WeaponMesh`의 포즈·월드 배치를 복사한다.
- 소유와 부착을 분리한다. 잔상은 캐릭터 루트·메시·소켓에 부착하지 않으며 Leader Pose도 쓰지 않는다. 포즈를 한 번 복사하고 뼈 변환·바운드를 직접 갱신한 뒤 컴포넌트 Tick 없이 고정한다. 무적이 끝난 뒤 원본이 넉백·물리 반응을 받아도 잔상의 배치와 뼈 자세는 바뀌면 안 된다.
- 새 `M_JustDodge_Afterimage`는 Unlit·Translucent·스켈레탈 메시 사용이며 프레넬로 검정 몸체와 약한 흰색 가장자리를 섞는다. 현행 값은 몸 색 `(0.006,0.006,0.006)`, 가장자리 `(0.35,0.35,0.35)`, 불투명도 0.4→0.6, 프레넬 지수 4·기본 반사율 0.02다. 사용자 무기 교체·양방향 출력·난전 중 안정성 확인 뒤 유지한다. 밝기·남는 시간의 별도 선호 평가는 보고받지 않았다.
- 몸·무기 공유 MID에 `StartTime`을 한 번 설정하고, 머티리얼이 `saturate(1 - (GameTime - StartTime) / 0.35)`로 페이드한다. CPU Tick으로 파라미터를 갱신하지 않는다. 0.35초 뒤 타이머가 숨기고 다음 성공에 재사용한다. 숨김 중 재진입은 기존 잔상을 덮어쓰지 않는다. 원본 오버레이·충돌·물리·그림자·복제는 사용하지 않는다. 종료 시 타이머 정리와 소유 컴포넌트 정리를 따른다.
- 모든 플레이어에게 보이는 성공 신호다.
- 대안: Niagara 스켈레탈 메시 샘플링. 실루엣이 흐려 "그 자리에 있던 몸"이 덜 읽혀서 차선으로 둔다.
- 비용: 플레이어당 몸 하나·무기 최대 하나의 추가 스킨드 메시이며, 드로우콜은 메시 섹션 수에 따라 늘어난다. 재사용은 반복 생성·파괴 비용을 줄이고, Tick 제거는 애니메이션·CPU 페이드 갱신을 줄이지만 스키닝·반투명 렌더링 비용은 남는다. 측정은 그래픽스 프로파일링에서 함께 한다(Roadmap §5).

### 2.3 로컬 화면 연출 [그래픽스 작업으로 이관, 트리거 연결은 V5]

여기에는 연출 의도와 트리거만 남긴다. 구현은 그래픽스 작업의 "화면 효과 레이어"에서 한다(J-012).

- 의도: 성공한 본인 화면에만 0.25~0.3초 동안 채도를 낮추고, 색수차와 중앙을 향한 방사형 블러를 건 뒤 원래대로 돌린다. 월드 슬로모 없이 "시간이 늘어진 느낌"을 낸다.
- 트리거: 성공 큐가 소유 클라이언트에서 `IsLocallyControlled()`일 때 화면 효과 레이어에 "저스트 회피" 효과와 강도 커브를 요청한다. 인터페이스 이름은 그래픽스 작업이 정한다.
- 카메라 쉐이크와 FOV 펀치는 렌더링이 아니므로 V3a에 남긴다(§2.5).

### 2.4 버프 오라 [부착 입자는 V3a, 이동 꼬리는 V3b, 림라이트는 그래픽스 작업으로 이관·On/Off 연결은 V6]

- 버프 GE의 지속 큐(`GameplayCue.LNP.JustDodge.Buff`, Actor 큐)로 구현한다. GE가 갱신돼도 큐는 유지되고, GE가 끝나면 제거된다.
- **파티클:** 발밑과 손 주변에 약한 무채색 입자를 띄우고, 이동 중에는 짧은 꼬리를 남긴다(J-021). 본인과 동료 모두 버프 상태를 알아볼 수 있다.
  - V3a: 캐릭터에 부착된 로컬 스페이스 입자(발밑·손).
  - V3b: 이동 꼬리. 입자가 월드에 남아야 해서 월드 스페이스가 필요하다. 그래픽스 단위 N이 끝나 §4의 월드 스페이스 규칙을 따르면 된다(2026-11-10).
- **림라이트(이관):** 무채색의 약한 펄스와 밝기 대비를 검토한다(J-021). 오버레이 머티리얼, CustomDepth/스텐실 중 무엇으로 할지는 그래픽스 작업의 캐릭터 강조 채널 설계를 따른다.
- V3a 구현은 표시용 메시의 `hand_l`·`hand_r`에 공통 `NS_JustDodge_Aura`, `root`에 `NS_JustDodge_FootAura`를 연결한다. 발밑의 검정 연기에는 DepthFade 6cm인 전용 `M_JustDodge_FootSmoke`를 쓴다. 원본 연기의 120cm 페이드는 바닥 근처 오라를 과도하게 희미하게 했다. 외형·어두운 곳 시인성·2인 양방향 출력·갱신/만료와 콘솔 사망/리스폰을 사용자가 확인했다. 흰색 강조 자체는 인지하지 못했으나 전체 시인성이 괜찮다는 평가로 현행 수치를 유지한다. 수치·검증 범위는 [V3a 실행서](../phases/PhaseV3a_CameraAura.md)가 소유한다.

### 2.5 카메라 [V3a]

- 짧은 카메라 쉐이크를 넣는다. 기존 `ULNPGameplayCueNotify_VFXSound::CameraShake`가 이미 로컬 컨트롤러에서만 재생된다. 단, 엔진 기본 `UDefaultCameraShakeBase`는 체감이 거의 없으므로(Parry §8) 전용 쉐이크 클래스를 만든다.
- FOV 펀치(약하게 넓혔다가 돌아오기)는 Gameplay Cameras 리그([TechDesign_CharacterMovement.md](../../TechDesign_CharacterMovement.md) §2.4)를 거친다. ADS 중에는 생략하고, 펀치 중 ADS 진입 시 종료하며 조준을 풀어도 재개하지 않는다(J-024).
- V3a 현행: 소유 플레이어가 성공 큐 수신 시 로컬 시작 시각을 기록한다. `CR_ThirdPerson`의 기본 FOV 뒤 `LNPJustDodgeFOV` 노드가 +3°까지 0.04초 동안 넓히고 0.16초 동안 복원한다. 양 구간은 SmoothStep으로 잇는다. 이전 FOV를 저장·복원하지 않고 매 프레임 리그 결과에 가산하므로 ADS·활공 리그의 기본값을 덮어쓰지 않는다. 사용자 시각 평가와 본인만 카메라 효과가 나오는 2인 검증을 통과했다. ADS 전환의 정확한 런타임 경계는 별도 미확인이다.

## 3. 그래픽스 작업과의 경계

## 4. Niagara 함정 (모든 비주얼 단위 공통)

원본 근거는 [그래픽스 단위 N 로그](../../Graphics/history/UnitN_Log.md)다(2026-11-10). [TechDesign_ParrySystem.md](../../TechDesign_ParrySystem.md) §8은 증상 기록이다.

- **월드 스페이스는 써도 된다.** 원점에서 24,000cm 떨어진 구 내벽에서도 정밀도·바운드 문제가 없다(입자 덤프로 원점과 같은 동작 확인). 과거에 월드 스페이스 스파크가 1px도 안 보였던 원인은 아래 `PointAttractionForce`였다.
- **`PointAttractionForce`를 중력·부력 용도로 쓰지 않는다.** `Use Falloff=false`이면 힘이 끌개까지의 거리에 비례한다. 월드 원점이 끌개이면 첫 틱에 입자가 1.5km 밖으로 날아가고, 끌개 근처에서도 지수적으로 폭주한다. 로컬 스페이스에서는 끌개가 컴포넌트 원점이 될 뿐 같은 문제가 있다.
- **구면 중력이 필요하면** 월드 스페이스 이미터에 `GravityForce`를 넣고, `Coordinate Space=World`, `Gravity` 입력에 HLSL 식 `normalize(Particles.Position) * 980.0`을 쓴다. 내벽 세계에서 바깥 방향이 아래이므로 이 부호가 낙하이고, 상승(연기 등)은 부호를 반대로 한다. 세 방향에서 바깥 가속도 911~978을 확인했다. 전제는 구 중심이 월드 원점이라는 것이다.
- 로컬 스페이스 이미터에 위 식을 그대로 쓰면 안 된다. `Particles.Position`이 로컬 좌표라 방향이 틀린다(미검증). 수명이 짧은 로컬 버스트는 지금처럼 힘 모듈을 끈다.
- 식 입력을 바꾼 뒤에는 입자 덤프로 실제 반영을 확인한다. 단위 N의 첫 측정은 식이 들어가기 전의 기본값 `(0,0,−980)`으로 돌았다. Niagara 에디터 미리보기는 원점에서 돌기 때문에, 미리보기가 정상이어도 원거리에서 깨질 수 있다. 확인은 24,000cm 근처에 배치하고 입자 덤프(`bDumpDebugEmitterInfo`)로 한다.
- 플래시 스프라이트에는 `ScaleSpriteSize` 커브를 넣는다. 크기가 고정이면 원이 켜졌다 꺼지는 그림이 된다.
