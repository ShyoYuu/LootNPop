# 저스트 회피 검증 규약

> 상태: 기준 설계
> 마지막 갱신: 2026-11-06

## 1. 실행 환경

| 환경 | 용도 |
|:---|:---|
| PIE 1인 (TestMap03) | 경로별 기본 동작 |
| PIE 리슨 2인 | 게스트 대시가 서버 판정을 받는지, 관전자 화면, 보정 캡슐 |
| PIE 리슨 2인 + 네트워크 에뮬레이션 (`PktLag` 50/100) | 지연 체감, J-007·J-010 재검토 (Phase 3) |

- 적의 공격을 재현할 편성: 기본 `DA_MassSpawnConfig`는 그대로 두고, 검증 편성 에셋에 `LNP.Spawn.ConfigOverride`를 걸어 쓴다. 근접·원거리(직선·포물선)·폭발 투사체를 쓰는 종을 포함한다.
- 화염 경로는 두 번째 플레이어가 화염방사기로 쏘는 PvP로 재현한다(다른 팀 설정 필요).
- 사용자 플레이 테스트는 한 번에 정보를 많이 얻도록 시나리오를 요인설계로 묶어 요청한다.

## 2. 공통 회귀 (모든 Phase)

- 가드·패링(근접·투사체 반사)이 기존대로 동작한다. 대시하지 않으면 결과가 이전과 같아야 한다.
- 대시하지 않은 일반 피격·경직·넉백이 그대로다.
- 대시 이동, 대시 점프, 쿨다운 HUD 파이가 그대로다.
- 리슨 2인에서 대시할 때 보정 캡슐이 늘지 않는다(`Mover.LocalPlayer.ShowCorrections`, 필요하면 `LNP.Spawn.EnemyDensity 0`).
- 로컬 보정 표시는 게스트 콘솔에서 `Mover.LocalPlayer.ShowCorrections`를 인자 없이 한 번 입력해 켠다. 토글이므로 다시 입력하면 꺼진다. 초록은 보정 후 위치, 빨강은 보정 전 위치, 노랑은 위치 차이가 없는 보정이다. 기존 `mover.debug.ShowCorrections 1`은 Gameplay Debugger에서 선택한 서버 제어 대상용이며 로컬 플레이어 표시를 켜지 않는다. 재스폰하면 새 폰에서 다시 켠다.
- 깨끗한 트리에서 Build.bat이 통과한다.

## 5. 비주얼 시나리오 (트랙 V)

### 임시 대시 미리보기

적 공격에 맞춰 성공해야 하는 불편을 줄이기 위해 `LNP.Debug.JustDodgePreview`를 둔다(2026-11-05 사용자 요청). 기본값은 0이다.

- `LNP.Debug.JustDodgePreview 1`: 로컬 플레이어가 대시할 때마다 성공 큐의 비주얼을 즉시 재생한다. 허공 대시로 사라짐·나타남을 비교할 수 있다.
- `LNP.Debug.JustDodgePreview 0`: 미리보기를 끈다. 실제 서버 확정 저스트 회피 성공 시에만 비주얼이 나온다.
- 판정·버프를 만들지 않으며, 큐를 네트워크로 전파하지 않는다. 리시뮬레이션에서도 반복 재생하지 않는다. 원격 관찰과 성공 판정·큐 지연 검증은 반드시 0으로 끄고 한다. 켠 채 실제 성공하면 실제 큐도 별도로 도착할 수 있다.
- 임시 코드 위치는 `Movement/LNPCharacterMoverComponent.cpp`의 CVar 선언과 `ExecuteDash` 안의 미리보기 분기다. 비주얼 튜닝이 끝나면 두 블록과 전용 include(`GameplayCueManager.h`·`HAL/IConsoleManager.h`)를 함께 제거한다.

### 원격 플레이어 Ghost 착탄 A/B

- `LNP.Projectile.RemoteImpactPredictMinSpeed 3000`: **기본값(J-027)**. Ghost의 현재 탄속이 이 값 이상이면 원격 플레이어를 로컬 예측하고, 미만이면 서버 착탄 큐를 기다린다.
- `LNP.Projectile.RemoteImpactPredictMinSpeed 0`: 항상 로컬 예측. 원격 플레이어에도 로컬 코스메틱 충돌·소멸·임팩트를 예측한다. 대시 상태를 받았으면 원격 무적 미러를 사용한다. 교체 전 `PredictRemotePlayerImpact 1`과 같다.
- `LNP.Projectile.RemoteImpactPredictMinSpeed 9999999`: 항상 대기. 원격 플레이어 접촉의 소멸·임팩트를 서버 착탄 큐에 맡긴다. 교체 전 `PredictRemotePlayerImpact 0`과 같다.
- 어느 값이든 Ghost의 비행·지형 충돌·수명 만료, 로컬 플레이어와 적에 대한 코스메틱 충돌은 유지한다. 서버 판정·피해·저스트 회피 성공은 바꾸지 않는다.
- 게스트 콘솔에서 실행한다. PIE 중 즉시 전환되며 다음 프로세서 실행부터 적용한다. 단일 프로세스 PIE에서는 CVar가 같은 프로세스의 월드에 공유되지만 서버 판정 분기에는 영향을 주지 않는다. 이미 소멸한 탄은 복구하지 않는다.
- 비교: 현재 단발·반경 60을 유지하고 미리보기 0·PktLag 0에서 0과 9999999를 번갈아 설정한다. 호스트 실제 저스트 회피를 게스트에서 관찰해 관통·오소멸, 일반 명중의 늦은 소멸/관통 체감, 뒤 지형 착탄을 비교한다. 필요하면 두 창 PktLag 50도 추가한다. 종료 뒤 CVar 3000과 두 창 PktLag 0으로 복원한다.
- 대기 경로에서는 서버 결과가 도착할 때까지 일반 명중 탄도 더 진행해 보일 수 있다. 서버 큐 전에 지형·다른 대상에서 로컬 소멸할 가능성도 유지하므로, 모든 종류의 Ghost 소멸을 서버 전용으로 바꾸는 전역 스위치는 아니다.
- 서버 착탄 경로 진단은 기존 `LNP.Debug.Dodge 1`로 켠다. `[GhostImpact] Send`의 `player/key/index`와 `Receive net=3`의 값을 대조한다. 게스트의 `destroyed=1`은 살아 있던 Ghost를 찾아 정리했다는 뜻이며, 로컬에서 먼저 없앤 탄은 0일 수 있다. 리슨 호스트 `net=2`에는 Ghost가 없으므로 0이 정상이다. 2026-11-06 수정 전에는 수신 10건 모두 key=0으로 바뀌어 검색에 실패했다. 식별자 UPROPERTY 수정 뒤 에디터를 완전히 재시작한 빌드로 일반 피격부터 확인한다.
- 2026-11-06 교체 뒤 A/B: 느린 NPC 탄에서 `RemoteImpactPredictMinSpeed 0`은 저스트 회피 성공 탄이 가끔 막혔고, `999999`는 한 번도 막히지 않았다. 일반 명중의 관통은 두 값 모두 체감하기 어려웠다. 기준 이상의 실제 고속 탄은 시험하지 않았다.
- 2026-11-06 A/B 결과(교체 전 `PredictRemotePlayerImpact` 기준): 실제 값 0 적용을 확인한 상태에서 PktLag 0·양쪽 50 모두 회피 탄 소멸이 관찰되지 않았고 일반 명중 지연도 거의 체감되지 않는다고 사용자가 확인했다. 사용자는 이번 세션에서는 CVar를 보존하고 기본값만 0으로 두기로 결정했다(J-026). 양쪽 PktLag 50은 편도 각각 +50ms, RTT 합계 약 +100ms이며 RTT 200ms 검증으로 기록하지 않는다.

### 임시 성공·실시간 재생·선택적 정지 명령

사용자가 실제 성공 후 2.5초 안에 마우스를 풀고 에디터 Pause를 누르는 절차가 비현실적이라고 지적해 추가했다(2026-11-05).

- `LNP.Debug.JustDodgeTest`: 1인 또는 리슨 호스트 PIE 콘솔에서 실행한다. 로컬 플레이어에 정상 `FLNPJustDodgeCommand::ApplyEntry`를 호출해 버프 GE와 성공 큐를 실시간으로 재생한다. 기본값은 멈추지 않는다. 0.3초 뒤 부착 본·월드 위치·배율·활성 여부·이미터별 입자 수만 기록한다. 재입력하면 정상 스택 규칙으로 버프가 갱신된다.
- `LNP.Debug.JustDodgeTest pause`: 성공 처리 뒤 0.3초에 에디터 방식(`bDebugPauseExecution`)으로 정지해 샘플을 남긴다. 정지 뒤 콘솔을 닫고 Shift+F1로 마우스를 풀어도 시간 제한이 없다.
- `LNP.Debug.JustDodgeTest resume`: 예약한 정지를 취소하고 게임 일시정지와 에디터 일시정지를 명시적으로 해제한다. 에디터 상단 Resume으로도 새 정지를 해제할 수 있다. 일반 `pause` 콘솔 명령으로 재개하라는 과거 안내는 폐기했다.
- 공격 접촉 판정·대시·무적 창을 만들지 않는 연출 조사용 명령이다. 소비 플래그·대시 방향은 호출 중에만 빌리고 복원한다. 실제 성공·지연·갱신 검증을 대신하지 않는다. 로그의 `attack=Debug`는 실제 공격 성공 건수에서 제외한다.
- 임시 구현은 `GAS/GameplayCues/LNPGameplayCueNotify_JustDodgeBuff.cpp`의 `GLNPJustDodgeTest` 블록과 전용 조건부 include다. Shipping에서는 제외한다. 비주얼 튜닝이 끝나면 함께 제거한다.
- 입자 수 로그는 공통 `NS_JustDodge_Aura`와 발밑 `NS_JustDodge_FootAura` 모두를 기록한다. Niagara 풀 컴포넌트의 소유자는 캐릭터가 아닌 WorldSettings이므로 실제 부착 부모·소켓과 구분한다.

## 6. 로그 판정 문자열

로그는 `LNP.Debug.Dodge 1`, 화면 문구(`IFRAME`·`IFRAME BLOCK`·`JUST DODGE`)는 `LNP.Debug.ShowDodge 1`로 켠다. 둘 다 기본은 꺼짐이다. 문구 규약은 `Architecture.md` §7에 있다.

- ⚠️ PvP 경로(스플래시·화염을 다른 플레이어가 쏘는 경우)는 `LNP.Team.Set 1 2`를 빼먹으면 탄이 같은 팀을 통과해 `Judge`까지 가지 않는다. 그러면 로그도 피해도 없어 "무적이 잘 된다"로 오인하기 쉽다. 시작할 때 `[LNP.Team.Set] ... team 1 -> 2` 줄로 확인한다.

| 문자열 | 의미 |
|:---|:---|
| `[Dodge] IFrame open <폰> role=<역할> expiry=<시각> just=<길이> [press=<시각> uplink=<ms>]` | 대시가 무적·저스트 창을 열었다 (권위·오토노머스). `press`·`uplink`는 서버의 원격 게스트 줄에만 있다(피격 유예의 누름 추정) |
| `[Dodge] IFrame ignored path=<Melee\|Projectile\|Splash\|Flame> player=<폰>` | 무적으로 무시한 피격 (서버) |
| `[Dodge] JustDodge success player=<폰> attack=<Melee\|Projectile>` | 저스트 회피 성공 (서버, 대시당 최대 1줄) |
| `[Dodge] Ghost impact skipped player=<폰>` | 클라 Ghost가 무적 때문에 예측 임팩트를 생략 (클라, 탄 하나당 1줄) |
| `[Dodge] Hit path=<Melee\|Projectile> player=<폰> sinceJust=<ms\|->` | 저스트 회피 대상 공격에 그대로 맞음 (서버). 놓친 저스트 회피 집계용 |
| `[Dodge] Success cue arrived player=<폰> local=<0\|1> role=<역할>` | 성공 큐 도착 (모든 머신, `local=1`이 소유 화면). 연출 지연 집계용 |
| `[Dodge] Grace player=<폰> rtt=<ms> uplink=<ms> hold=<ms>` | 피격 유예 보류 길이 미러 (서버, 값이 10ms 이상 바뀔 때). 호스트는 `hold=0` |
| `[Dodge] Grace release path=<경로> player=<폰> held=<ms>` | 보류된 피격 효과를 적용했다 (서버) |
| `[Dodge] Retro <Dodged\|JustDodged> path=<경로> player=<폰> held=<ms>` | 늦게 도착한 대시가 보류된 피격을 소급 회피했다 (서버). 화면 문구는 `IFRAME BLOCK <경로> RETRO` |
| `[Guard] Block success` | 기존 가드 로그 — 회귀 확인용 |

- 집계: `Scripts/Profiling/AnalyzeDodgeLog.py <로그> --since HH:MM:SS [--until HH:MM:SS]`. 소급된 `Hit`은 놓침에서 빼고, 서버가 거부한 누름을 `press-then-hit`(누른 뒤 서버 피격 — 피격 유예가 없애야 하는 유형)과 `hit-then-press`(이미 맞은 뒤 누름 — 호스트도 잃는다)로 나눈다. `press estimate - actual press`는 누름 추정 오차다(음수 = 서버가 이르게 추정).
- 피격 유예 A/B: `LNP.HitGrace.Enable 0|1`을 한 PIE 세션 안에서 바꿔 구간을 나눈다. 지연은 두 창 모두 `net.PktLag=N`.
