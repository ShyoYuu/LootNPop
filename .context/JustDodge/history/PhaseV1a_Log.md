## 2026-11-05 — 단위 1 구현

- 사용자가 단위 1 진행을 승인했다. 캐릭터 클래스 크기가 바뀌므로 전체 빌드 전에 에디터 저장·종료를 요청했고, 사용자로부터 종료 확인을 받았다.
- 성공 큐가 `ALNPCharacterBase::ApplyJustDodgeBlink`를 호출한다. 캐릭터가 몸·무기·애니메이션 원본 메시의 숨김 및 숨은 그림자 상태를 저장하고, 0.12초 뒤 복원한다. 원본 메시를 포함하는 이유는 숨은 그림자를 막되 기존 상시 숨김을 보존하기 위해서다.
- 기존 `bVisible`과 무기 장착 경로는 변경하지 않았다. 부재 중 장착·맨손 전환은 장착 코드가 갱신한 상태를 유지한다(코드 검토 근거, PIE 실측 대기).
- 재진입은 상태를 재저장하지 않고 같은 타이머를 갱신한다. 랙돌 진입과 EndPlay에서 즉시 복원·타이머 해제한다. UObject 바인딩 타이머와 약한 컴포넌트 참조를 사용한다.
- Dedicated Server와 이미 랙돌인 대상은 순보를 시작하지 않는다. 판정·버프·이동·월드 시간·콜리전은 변경하지 않았다. 에셋 변경도 없다.
- 에디터 종료 확인 뒤 권한 확장으로 `Build.bat LootNPopEditor Win64 Development <uproject> -WaitMutex -NoHotReloadFromIDE`를 실행했다. UHT와 14개 작업이 성공했고, `Result: Succeeded`, 종료 코드 0, 총 100.65초였다. 변경한 두 `.cpp`는 adaptive non-unity로 컴파일됐다. 커밋 뒤 클린 트리·전체 unity 검증을 한 것은 아니다.
- `git diff --check`를 통과했다. 재진입·무기 교체·사망·종료 처리는 코드 검토까지 했으며 런타임 통과로 기록하지 않는다. 사용자에게 PIE에서 성공·일반 대시·맨손·무기 교체·사망 표시 확인을 요청한다. 다음 단위는 사용자 확인 후 진행한다.

- Niagara 에셋 제작을 위해 사용자에게 프로젝트 에디터 실행과 PIE 종료를 요청했다. 아직 두 시스템 생성·연결 및 원거리 픽셀 검증은 수행하지 않았다.

## 2026-11-05 — 사용자 시각 평가: 무채색·전신 범위로 조정

- 사용자가 미리보기에서 속도선이 작고 배 근처에만 보이며, 원형 플래시가 어색하다고 평가했다. 보라색 대신 검정 중심의 무채색과 가운데의 약한 흰색 강조를 요청했고, 낮은 시인성도 허용했다. 기존 버전의 실제 픽셀 출력은 이 피드백으로 확인했다. 색 결정은 J-021, 전신 범위와 플래시 선택은 J-022에 기록했다.
- PIE가 실행 중이라 도구로 종료한 뒤 작업 대상 Niagara 두 시스템만 먼저 저장하고 수정했다. 캐릭터 함수·큐 연결·미리보기 코드·판정·버프는 변경하지 않았다.
- 기존 `M_LNP_Spark`·`M_DepthFade_SpriteSimple`은 Additive여서 검정이 보이지 않는 것을 확인했다. 프로젝트의 `M_LNP_Smoke`가 Unlit·Translucent·TwoSided·Niagara Sprite용이며 ParticleColor를 사용하므로, 몸체 입자에 재사용했다. 새 머티리얼·인스턴스는 만들지 않았다.
- 몸체 `Sparks`: 사라짐 36개·나타남 28개, 색 `(0.006,0.006,0.006,0.92)`, 수명 0.12~0.18초. 반경 55cm 구 표면을 `(0.7,0.7,1.7)`로 늘려 높이 약 187cm에 분포시켰다. 스프라이트는 12×120~20×200cm이며, 알파는 0→1→0.8→0으로 완만하게 변한다.
- 이전 `Flash`는 원형 플래시 대신 중심 강조선으로 재구성했다. 두 시스템 모두 5개, 색 `(0.85,0.85,0.85,0.45)`, 수명 0.16초, `M_LNP_Spark`의 2×65~4×125cm 속도 정렬 스프라이트다. 반경 14cm·배율 `(0.65,0.65,2)`의 중앙 영역에 분포시키고, 크기·알파가 서서히 변하게 했다. 나타남 쪽은 원점을 향해 160cm/s로 모인다. 고정된 큰 원형 스프라이트는 없다.
- 네 이미터 모두 로컬 스페이스·단발과 힘 모듈 비활성 상태를 유지했다. 루프 길이는 입자보다 긴 0.22초다. 두 Niagara 에디터를 열어 컴파일·스택을 검사했고 각각 UpToDate, stale=false, 오류 0·경고 0이다. 작업 대상 두 시스템만 지정해 저장했고 결과는 성공이다.
- `SearchCVars`로 미리보기 현재값 1을 확인했다. 사용자에게 PIE를 다시 시작해 전신 범위·검정/흰색 비율·플래시가 빠진 느낌을 재평가해 달라고 요청했다. 새 버전의 시각 평가와 단위 3 진행은 아직 미확인이다.

## 2026-11-05 — 사용자 시각 평가: 평행한 속도선과 흰색 가시성

- 사용자는 전신·무채색 버전이 원한 느낌에 가까워졌다고 평가했다. 다만 흰색이 전혀 느껴지지 않고, 검은 선은 대시 방향의 속도선보다 무작위로 돋아난 가시처럼 보인다고 했다.
- 실제 입력을 확인하니 사라짐은 몸체 28도·강조 20도 콘으로 퍼졌고, 나타남은 From Point의 음수 속도로 방사형 수렴을 했다. 이를 네 이미터 모두 로컬 +X·콘 각도 0도·650cm/s의 평행 이동으로 바꿨다. 나타남의 From Point 모듈은 제거했다. 렌더러의 `VelocityAligned` 정렬은 유지했다.
- 나타남의 컴포넌트 회전은 기존 캐릭터 전방을 사용해 옆·뒤 대시의 축과 어긋날 수 있었다. 타이머가 `DashDirection`을 값으로 보존하고 `FinishJustDodgeBlink`에 넘기게 했다. 복원 위치의 구면 접평면에 다시 투영해 사라짐과 같은 대시 축으로 회전시킨다. 클래스 상태 멤버나 반사 레이아웃 추가는 없다. 사망·EndPlay 취소는 기존처럼 버스트 없이 복원한다.
- 흰색 강조는 두 시스템 모두 색 `(18,18,18,0.70)`, 6개, 크기 5×90~7×150cm로 보강했다. 검은 몸체는 이전 값을 유지했다. 흰색 렌더러 `SortOrderHint=1`, 몸체 0으로 설정했다. 크기·알파 곡선은 유지해 원형 플래시를 되살리지 않았다.
- C++ Live Coding 도구 결과 `Result: Success`, `Live coding succeeded`를 확인했다(UBT 12개 작업, 249.33초). 두 Niagara 에디터를 열어 컴파일·스택을 검사했고 모두 UpToDate·stale=false·오류 0·경고 0이었다. 네 이미터의 실제 입력과 렌더러 순서도 다시 읽어 확인했다.
