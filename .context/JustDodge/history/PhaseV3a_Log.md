# V3a 작업 기록

## 2026-11-05 — 조사·구현안 정리

- `README.md`·`Current.md`·`Decisions.md`와 비주얼 설계·카메라 공통 설계를 확인했다. 다음 구현 단위는 V3a이며 V4a 착수 전 사용자에게 계속 진행할지 확인한다.
- 성공 큐 부모의 `CameraShake`는 로컬 컨트롤러에서만 재생된다. 버프 GE는 `AggregateByTarget`·스택 한도 1·시간 갱신·`bSuppressStackingCues=true`다.
- 기록상 `.Buff`는 빈 `GameplayCueNotify_Looping` 에셋이다. 엔진 소스에서 지속 큐의 시작·제거·재활용 처리를 확인했다. 프로젝트 캐릭터가 `APawn`이므로 기본 부착 대상은 루트 캡슐이며, 양손 부착에는 표시용 메시를 지정해야 한다. 현재 라이브 에셋 상태는 아직 확인하지 못했다.
- 사용자에게 일반 시점 +3°·총 0.2초 FOV 펀치와 짧은 쉐이크를 제안했다. ADS 중 FOV 펀치 생략·ADS 진입 시 종료 여부는 응답 대기다.
- 현재 세션에 Unreal MCP 도구가 직접 노출되지 않는다. `.mcp.json`의 대상은 `http://127.0.0.1:8000/mcp`다. 로컬 HTTP 확인은 샌드박스의 소켓 접근 거부로 실패했으며 서버 장애로 판단하지 않는다. 별도로 `UnrealEditor` 프로세스가 없음을 확인하고 사용자에게 프로젝트를 열어 PIE 정지 상태로 두도록 요청했다.
- 실행서는 초안으로 작성했다. 런타임 코드·에셋 변경과 빌드·PIE 검증은 아직 하지 않았다.

### 구현·Live Coding·에셋 연결

- 사용자가 ADS 중 FOV 펀치를 생략하도록 확정했다(J-024). 일반 시점은 +3°·진입 0.04초·이탈 0.16초 SmoothStep 초안이다. 로컬 성공 큐 수신 시 시작하며, ADS 진입·사망 시 시작 시각을 폐기한다. 전용 카메라 노드가 기본 FOV 뒤 가산한다.
- 권한 확장 실행으로 프로젝트의 8000번 MCP에 Initialize·읽기 도구 호출을 성공했다. 초기 프로세스 미관측·소켓 거부는 샌드박스 관측 범위였으므로 이후 라이브 접속 결과를 기준으로 한다. PIE=false 확인 뒤 관련 Niagara·Blueprint Agent Skill을 읽고 대상 에셋을 저장했다. 기존 세 에셋 사본은 `Saved/Temp/V3aBefore/`에 보관했다.
- `LNPJustDodgeFOVCameraNode`, `LNPGameplayCueNotify_JustDodgeBuff` 두 네이티브 클래스를 추가했다. 지속 큐는 표시용 메시를 `TargetAttachComponent`에 지정하고 엔진의 기존 시작·제거·재활용 경로를 사용한다. 별도 Actor Tick이나 타이머를 추가하지 않았다.
- Live Coding: UHT 5개 생성 파일, 14개 컴파일 작업, UBT 186.71초 성공. HTTP 요청은 180초 제한으로 먼저 끝났지만 엔진 로그에 `CompileLiveCoding: Result: Success`와 새 클래스 2개 반영을 확인했다. 마지막 socket_send_failure는 끝난 HTTP 요청에 결과를 보내려던 오류이며 빌드 실패가 아니다. 에디터 종료 뒤 정규 전체 빌드는 아직 남는다.
- 카메라 리그 연결용 Python 초안은 `root_node` 속성이 Python에 노출되지 않아 에셋 수정 전 실패했다. 직접 확인하지 않은 속성 접근을 제안한 점을 사용자에게 설명하고 해당 스크립트를 삭제했다. 사용자가 `CR_ThirdPerson` Sequence에 마지막 9번 핀을 추가해 `LNPJustDodgeFOV`를 연결·Build·저장했다. 14:24:30 UTC 저장 로그로 확인했다.
- `CS_JustDodge`는 위치·FOV 흔들림 없이 작은 회전만 0.16초 재생한다. `bSingleInstance=true`, Pitch/Yaw/Roll 0.25°/0.15°/0.1°, 주파수 25/24/22Hz, 진입 0.02초·이탈 0.1초다. 성공 큐의 `CameraShake`에 연결했다.
- 오라 에셋은 기존 `NS_JustDodge_Disappear` 복제본 `NS_JustDodge_Aura`다. 두 CPU 로컬 스페이스 이미터의 시스템·이미터 루프를 Infinite·0.3초로 바꾸고 작은 검정 4개·약한 흰색 1개 버스트를 반복한다. 검정 수명 0.35~0.5초, 흰색 0.3초, 로컬 +Z 12cm/s다. 전신 속도선 크기·색과 원본 에셋은 바꾸지 않았다.
- 실제 표시 메시 `SKM_Manny_Simple`의 `root`·`hand_l`·`hand_r` 본을 조회해 확인했다. 버프 큐를 새 네이티브 지속 큐로 재부모화하고 해당 본 3곳에 오라를 연결했다. 발밑 배율 1.6·양손 0.65, 그림자 없음, 중복 WhileActive 허용 안 함, OnRemove 자동 정리 유지다.
- 큐 BP 3개 컴파일과 오라 `UpToDate`·컴파일 오류/경고 없음·스택 오류 0/경고 0을 확인했다. 정보 5건은 복제한 기본 모듈의 버전 업그레이드 안내다. 새 쉐이크·오라와 변경한 성공/버프 큐만 저장했다. 사용자가 저장한 카메라 리그는 별도로 보존했다.
- 사용자에게 1인 PIE의 미리보기 카메라 체감, 미리보기 0의 실제 성공 오라 2.5초·ADS 전환 검증을 요청했다. 런타임 시각 평가·2인 관찰·갱신/만료·리스폰은 아직 응답 전이며 통과로 기록하지 않는다. V3a 마감 뒤 V4a 진행 여부를 확인한다.

### 1인 평가 — 카메라 수치 유지·오라 미표시 조사

- 사용자 보고: 시야가 살짝 넓어졌다 돌아오는 효과와 작은 쉐이크는 아주 자연스럽다. 카메라 현행 수치를 유지한다. ADS 경계는 별도 통과 보고를 받지 않았다.
- 사용자 보고: 미리보기를 끄고 실제 성공을 냈지만 발밑·양손 오라는 인지하지 못했다. 발밑을 자세히 보아도 확인하지 못해 크기·대비·위치 등의 문제를 의심했다. 오라 시각 검증은 미통과다.
- 읽기 조사에서 버프 BP 부모·GameplayCue 태그·스폰 확률 1·중복 WhileActive 차단·OnRemove 정리 값은 유지됐다. `GetCueInfo`는 버프뿐 아니라 실제 동작하는 성공 큐도 None으로 반환한다. 소스가 Blueprint 에셋이 아닌 네이티브 큐 클래스 기준으로 Asset Registry를 필터하므로, 이 도구 결과만으로 런타임 미등록을 판정하지 않는다.
- 실제 생성·부착·입자 상태를 확인하려고 사용자에게 미리보기 0의 실제 성공 직후 PIE를 일시정지해 두도록 요청했다. 요청 시점에는 PIE=false였으며 런타임 샘플은 아직 확보하지 못했다. 원인이 확인되기 전에는 크기·대비를 임의로 올리지 않았다.

### 성공·자동 일시정지 명령

- 사용자는 2.5초 안에 실제 성공·Shift+F1·에디터 Pause를 잇는 조작이 간단하지 않다고 지적하고, 임시 성공 콘솔 명령 또는 입력에 Pause를 연결하는 조치를 요청했다. 과도한 수동 타이밍 요구였음을 인정하고 기존 요청을 철회했다.
- `LNP.Debug.JustDodgeTest`를 기존 오라 큐 cpp의 비Shipping 임시 블록에 작성했다. 권위 로컬 플레이어가 있는 PIE에서 기존 `FLNPJustDodgeCommand::ApplyEntry`를 호출하고 0.3초 게임 시간 뒤 `APlayerController::SetPause(true)`로 멈춘다. `pause`로 재개한다. 소비 플래그·방향은 `TGuardValue`로 복원하고 대시·무적 창은 변경하지 않는다. 로그의 Debug 성공은 실제 공격 판정 증거가 아니다.
- 이 변경의 Live Coding을 진행 중이다. 오라 수치나 표현 에셋은 아직 바꾸지 않았다.

- 임시 명령의 첫 Live Coding은 성공했고, 사용자가 1인 PIE에서 실행했다. 14:44:46 UTC 로그에서 Triggered와 0.3초 뒤 paused=1을 확인했다. 이제 성공 타이밍이나 2.5초 내 수동 Pause 조작이 필요 없다.
- 정지 샘플에서 오라 큐 액터 1개와 오라 Niagara 컴포넌트 3개를 확인했다. Niagara 풀은 WorldSettings에 컴포넌트를 소유하며, 세 컴포넌트의 실제 부착 부모는 모두 플레이어 VisualMesh다. 상대 위치 0, 배율 1.6·0.65·0.65, 표시 켜짐·게임 숨김 꺼짐·주 렌더 패스 켜짐·OwnerNoSee 꺼짐을 확인했다. 따라서 생성 누락은 배제했다.
- `loopingSpawnResults`는 조회 JSON에서 빈 객체로 보였으나, 엔진 구조체의 Transient 결과 필드가 도구 직렬화에서 생략된 것이다. 이를 생성 실패로 해석하지 않고 월드 소유 컴포넌트를 별도로 조회했다. 자동 부착 설정의 socket=None도 실제 부착 소켓을 뜻하지 않는다.
- 생성·표시 플래그만으로 실제 입자 발생·정확한 부착 본은 확정하지 않았다. 현재 샘플 조사를 마쳤다고 알리고 PIE를 종료했다. 임시 명령이 멈추기 직전, Niagara 동시 틱을 마친 뒤 이미터별 입자 수와 부착 본·위치를 출력하도록 보강해 Live Coding 중이다. 아직 밝기·크기 에셋은 수정하지 않았다.
- 입자 수·부착 본 로그 보강은 Live Coding 성공, UBT 109.61초다. 사용자에게 새 1인 PIE에서 같은 명령을 한 번 더 실행하도록 요청했다. 재실행 샘플은 아직 대기 중이다.

- 사용자가 명령을 재실행했고 14:54:14 UTC 자동 정지를 확인했다. 새 PIE에서도 큐 1개·정상 크기·표시 상태의 오라 컴포넌트 3개를 다시 확인했다. 하지만 보강한 입자 수 로그는 출력되지 않았다. 이를 입자 수 0으로 판정하지 않는다. Live Coding 콘솔 콜백 패치 상태와 조회 경로를 분리해 확인해야 한다.
- 진단 명령의 조회는 실제 풀 소유자인 WorldSettings 컴포넌트 배열을 사용하도록 바꾸고, 매번 무조건 Snapshot 머리줄을 출력하게 했다. 부착 본·부모·입자 수 로그가 아예 없는 상황을 구분할 수 있다.
- 사용자에게 정규 전체 빌드를 위해 에디터 종료를 요청했고, 종료 응답 뒤 `LootNPopEditor Win64 Development -WaitMutex -NoHotReloadFromIDE -DisableAdaptiveUnity`를 처음부터 권한 확장으로 실행했다. 현재 빌드 중이다. 아직 오라 에셋 수치는 바꾸지 않았다.
- 정규 전체 unity 빌드 12개 작업·DLL 링크·메타데이터 기록 성공, 54.81초다. 사용자 및 다른 작업의 문서 변경이 있는 트리이므로 깨끗한 트리 빌드로 기록하지 않는다. 에디터를 다시 열었고 사용자에게 새 1인 PIE에서 같은 임시 명령을 실행하도록 요청했다.

### 양손 시인성 확인·발밑 깊이 페이드 수정

- 사용자 보고: 조정한 양손의 검정 오라는 확실히 보인다. 발밑은 여전히 보이지 않는다. 양손은 유지하고 발밑만 조사했다. 새 정지 로그(16:26:08 UTC)에서는 세 부착점 모두 active=1·입자 `[6 2]`로 생성·지속은 정상이다.
- 실제 화면에서도 발이 들어오는 구도에서 발밑의 검정 연기를 명확히 인지하기 어려웠다. 재사용 `M_LNP_Smoke`를 조사하니 DepthFade 기본 거리 120cm가 SphereMask×ParticleColor.Alpha와 곱해져 최종 Opacity로 연결돼 있었다. FadeDistance 입력은 비어 있어 기본값이 실제 사용된다. 바닥 근처에서만 약해지는 경로를 확인했다. 흰색 `M_LNP_Spark`에는 DepthFade가 없다.
