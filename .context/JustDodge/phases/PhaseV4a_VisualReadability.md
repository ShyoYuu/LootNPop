# V4a — 1차 체감 점검

> 상태: 주요 검증·세션 마감 — CVar 보존 및 기본값 0, 최종 빌드 통과 (2026-11-06)
> 선행: V1a·V2·V3a 주요 검증 마감. 각 실행서의 미확인 경계는 유지한다.

## 범위와 현재 결론

- 화면 효과·림라이트 없이 순보·잔상·카메라·부착 오라를 합친 체감을 확인한다.
- V-05: 사용자는 양쪽 PktLag 50에서도 대시 모션과 순보가 함께 잘 보이며, 0과 구분하기 어려울 만큼 자연스럽다고 확인했다. J-007(서버 확정 성공 연출, 예측 없음)을 유지한다. 큐 지연 수치는 이번에 재측정하지 않았다.
- 게스트가 관찰하는 호스트의 회피 탄 오소멸은 원격 무적 미러만으로 해소되지 않았다. 기본값 1의 로컬 예측에서는 체감상 약 절반의 소멸이 남았다.
- 착탄 식별자 전송 결함 수정 후 CVar 0을 실제로 적용해 PktLag 0·양쪽 50을 검증했다. 사용자는 회피 성공 때 탄이 소멸하는 경우를 보지 못했고, 일반 명중의 지연 소멸도 거의 체감되지 않으며 어색함 없이 자연스럽다고 평가했다. 이번 A/B 주요 검증은 통과다.
- 사용자는 이번 세션에서 CVar를 보존하고 기본값만 0으로 변경해 마무리하도록 정했다(J-026). CVar 삭제·정책 고정·원격 미러/진단 정리는 수행하지 않았다. 기본값·도움말 변경 뒤 정규 빌드가 통과했다. 지연 복원 여부는 별도 확인하지 않았고 사용자는 최종 빌드 전에 에디터를 종료했다.

## 구현과 결함 수정

- J-025의 원격 무적 미러: 기존 Mover 대시 시작 시각과 서버 무적 종료 오프셋으로 남은 시간만 로컬 월드 시계에 기록한다. 서버·소유 클라의 판정은 기존 ExecuteDash 경로를 유지한다. 공식과 소유권은 [아키텍처 §2.3](../design/Architecture.md)을 따른다.
- 착탄 비교 CVar: `LNP.Projectile.PredictRemotePlayerImpact` 1은 기존 로컬 예측·원격 무적 미러, 0은 원격 플레이어만 로컬 Ghost 충돌 후보에서 제외해 서버 착탄 큐에 맡긴다. 비행·로컬 플레이어·적·지형/수명은 유지한다. 보류/복구 큐는 만들지 않았다. 이 CVar는 이후 탄속 기준 `LNP.Projectile.RemoteImpactPredictMinSpeed`로 교체했다(J-027). 사용법은 [검증 규약 §5](../design/Validation.md)를 따른다.
- 값 0의 최초 시험에서 일반 명중의 HP·임팩트는 반영됐지만 Ghost가 화면 밖까지 남고 지면에서만 소멸했다. 송수신 로그 10건 모두 게스트 key=0·destroyed=0이었다. 서버 key=-213342가 게스트 key=0으로 바뀐 예로 Iris 파생 필드 전달 누락을 확정했다.
- `FLNPProjectileImpactContext` 식별자 3개에 UPROPERTY를 추가했다. 레거시 NetSerialize·키 계산·서버 피해 판정은 유지했다. 기존 네트워킹 문서의 GE 컨텍스트 직렬화 예외 설명도 정정했다.
- 진단은 기존 `LNP.Debug.Dodge 1` 아래 Send/Receive 로그를 사용한다. 호스트 net=2에는 Ghost가 없어 destroyed=0이 정상이다. 게스트 net=3의 키와 검색 결과를 본다. 정확한 코드·시간별 경위는 [V4a 로그](../history/PhaseV4a_Log.md)에 있다.

## 검증 근거

- 원격 미러: Live Coding(UHT 포함, UBT 84.35초), 자동화 `LootNPop.Combat.JustDodge.ProxyWindow` 1건 성공(0.0168초, 오류·경고 0). 시간 경계·서버 보정·직렬화 왕복·롤백 복사를 확인했다. 정규 unity 빌드 10개 작업·42.82초 통과.
- CVar 추가: Live Coding UBT 18.63초·등록/기본값 1 확인. 진단 로그 추가: Live Coding UBT 71.61초.
- 식별자 수정: 사용자 저장·에디터 종료 뒤 정규 `LootNPopEditor Win64 Development -WaitMutex -NoHotReloadFromIDE -DisableAdaptiveUnity` 빌드 통과(UHT 포함, 11개 작업·75.40초). 다른 작업 문서와 사용자 에셋 변경이 있는 트리이므로 깨끗한 트리 빌드로 기록하지 않는다.
- 최종 기본값 변경: 컴파일은 통과했지만 열린 에디터의 DLL 잠금으로 링크 실패(첫 실행 70.81초). 사용자 저장·종료 확인 뒤 같은 구성 재실행에서 남은 링크/메타데이터 2개 작업이 2.84초에 성공했다. 기본값·도움말만 바뀌어 같은 사용자 플레이 검증을 반복 요청하지 않았다.
- 수정 후 값 1 검증: 일반 명중의 소멸 정상. 저스트 회피 성공과 탄 소멸이 가끔 함께 보였다. 서버 성공 19건·소급 성공 0건으로 연출 오예측이라고 설명하지 않는다.
- 실제 값 0 검증: 로그에 0 적용·조회 확인, 양쪽 PktLag 50 입력을 확인했다. 현재값도 0이다. 지연 0 구간 서버 성공 18건·클라이언트 착탄 141건 중 Ghost 검색 성공 119건, 양쪽 50 구간 서버 성공 11건·클라이언트 착탄 37건 중 검색 성공 34건이다. 두 구간 모두 key=0 누락·소급 성공은 0건이다. 검색 실패를 오소멸률로 해석하지 않는다(이미 소멸·미스폰 가능).
- 값 0의 관통·일반 명중 지연 체감은 사용자 관찰 근거다. 개별 성공 탄의 전체 생존 경로나 성공률을 자동 측정한 것은 아니다.
- 난도 조사: 사용자는 적 DA의 링 1→0(7발→1발)·반경 15→60을 적용했다. 호스트 본인 화면에서도 난도가 비슷했고 산탄 수 감소의 영향이라는 설명에 동의했다. 에이전트는 사용자 에셋·난도 수치를 바꾸지 않았다.

기본값과 도움말/문서만 반영하고 CVar 1은 비교용으로 남긴다. 원격 미러·임시 테스트 명령·진단 로그도 유지한다. 이번 세션은 여기서 마감하며 다음 개발 단위를 자동으로 시작하지 않는다.

ADS의 정확한 전환 경계, 명시적 resume 콘솔, V1a 부재 중 무기 교체·사망, V2 잔상 수명 중 정확한 피격·넉백, 그래픽스 게이트 이후 효과는 새 검증 보고가 없다. 뒤 지형 착탄은 키 수정 전 사용자 확인 범위이고 수정 후 별도 집중 검증 보고는 없다. 공통 회귀 전체·깨끗한 트리 빌드·소급 성공 탄의 A/B를 통과했다고 확장해 기록하지 않는다.
