## 목표와 범위

서버가 확정한 저스트 회피 성공 큐 뒤에 사라짐 → 짧은 부재 → 나타남을 붙인다. 모든 관찰자에게 몸과 무기가 그림자까지 사라졌다 복원되고, 검정 중심의 전신 속도선과 약한 흰색 중심 강조가 실제 전투 위치에서 보여야 한다(J-021·J-022).

설계 원본은 [VisualDesign.md §2.1](../design/VisualDesign.md)이다. 잔상은 V2, 카메라·부착 오라는 V3a, 오버레이 필요성은 V6에서 재검토한다. 판정·버프·이동·큐 복제 경로는 변경하지 않는다(J-007·J-012·J-020).

## 착수 전 확인

2026-11-05 기준:

| 항목 | 실제 상태와 적용 지점 |
|:---|:---|
| 성공 큐 C++ | `ULNPGameplayCueNotify_JustDodgeSuccess::OnExecute_Implementation`은 도착 로그를 남기고 `VFXSound` 부모를 호출한다 |
| 성공 큐 에셋 | `/Game/GAS/GameplayCues/GCN_LNP_JustDodge_Success`가 존재하며, MCP `get_parent`로 위 C++ 부모를 확인했다 |
| 성공 큐 파라미터 | `FLNPJustDodgeCommand`가 `Location=방어자 위치`, `Normal=방어자 속도 방향`을 넣는다 |
| 표시 메시 | `ALNPCharacterBase::VisualMesh`가 몸, `WeaponMesh`가 무기다. 무기 장착은 `SetVisibility`를 사용한다 |
| 애니메이션 원본 | `AnimSourceMesh`는 처음부터 `SetVisibility(false)`·`SetHiddenInGame(true)`다. 순보 복원으로 노출하면 안 된다 |
| 타이머 선례 | `ALNPCharacterBase::ApplyHitStop`이 캐릭터에 묶인 약한 델리게이트를 사용한다. 순보는 별도 멤버 타이머로 재진입 시 갱신한다 |

MCP `GetCueInfo`는 성공 태그에 대해 빈 에셋 경로를 반환했다. 파일 존재와 실제 BP 부모 조회는 성공했으므로 이 결과만으로 큐 연결 실패로 판단하지 않는다. 런타임 연결은 기존 도착 로그와 PIE로 검증한다. 이번 준비 단계에서는 코드·에셋을 수정하거나 PIE를 실행하지 않았다.

## 현재 튜닝안

보라색 시작안은 사용자 시각 평가로 폐기했다(J-021). 전신 범위·무채색 비율·원형 플래시를 뺀 느낌을 다시 평가받고 구체 수치를 확정한다. 이전 수치는 로그에 보존한다.

| 항목 | 시작값/방식 |
|:---|:---|
| 색 | 검정 몸체 `(0.006,0.006,0.006,0.92)`와 가는 흰색 중심 강조 `(18,18,18,0.70)` |
| 부재 | 0.12초 |
| 나타남 버스트 | 전신 범위 입자 0.12~0.18초·가는 중심 강조 0.16초, 대시 축에 평행하게 흐르며 크기·알파 커브로 소멸. 원형 플래시는 제거 |
| 캐릭터 진입 함수 | `ALNPCharacterBase::ApplyJustDodgeBlink` |
| 복원 함수 | `ALNPCharacterBase::FinishJustDodgeBlink` |
| 사라짐 이펙트 | `NS_JustDodge_Disappear`, `/Game/Effects/Combat/` |
| 나타남 이펙트 | `NS_JustDodge_Reappear`, 같은 폴더, 대시 축에 평행한 전신 속도선·가는 중심 강조 포함 |

## 단위 1 — 메시·무기 숨김과 복원

1. 성공 큐가 캐릭터의 `ApplyJustDodgeBlink`를 호출한다. 타이머와 복원 책임은 캐릭터에 둔다. CDO인 Static 큐에 실행별 상태를 저장하지 않는다.
2. 몸·무기에 순보 전용 숨김을 적용한다. 기존 `bVisible`은 장착 코드가 계속 소유하게 하고, 기존 숨김·숨은 그림자 상태를 보존해 복원한다. 재귀적으로 모든 자식을 켜거나 Actor 전체를 숨기지 않는다.
3. `AnimSourceMesh`의 상시 숨김을 유지한다. 몸·무기의 숨은 그림자도 부재 중 그려지지 않게 하며, 원본 메시가 그림자를 내는 구성인지 확인한다.
4. 재진입은 첫 숨김 전 상태를 유지하고 동일 타이머를 갱신한다. 맨손·부재 중 무기 교체·사망·파괴에서 표시가 잘못 복원되거나 이전 폰의 콜백이 실행되지 않게 한다. 기존 사망·리스폰 처리를 개편하지 않는다.
5. Dedicated Server에서는 렌더링 처리를 생략한다. 움직임·애니메이션 시간·콜리전·ASC에는 손대지 않는다.

검증:

- 적절한 C++ 빌드 통과. 헤더·멤버 추가에 따른 안전한 재시작이 필요하면 요청한다. 에디터가 닫혀 있으면 프로젝트 규칙의 전체 빌드를 쓴다.
- 사용자 PIE 플레이로 성공 시 몸·무기·그림자가 잠깐 사라졌다 돌아오는지 확인한다. 일반 대시는 깜빡이지 않아야 한다.
- 맨손과 무기 장착 상태, 부재 중 무기 교체와 사망·리스폰의 복원 상태를 확인한다. 짧은 구간의 경계 조건은 코드 검토 근거와 실측 결과를 구분해 기록한다.

완료 후 사용자에게 단위 2 진행 여부를 확인한다. 이 단계에는 버스트와 잔상이 없어 사라짐만 보인다.

## 단위 2 — 사라짐·나타남 Niagara

1. 기존 전투 이펙트와 사용 가능한 Niagara 템플릿을 확인하고, 위 두 시스템을 만든다. 기존 가드·패링 에셋은 수정하지 않는다. 여러 에셋 변경 전후에 저장한다.
2. 사라짐은 큐 수신 시 해당 머신에서 표시 중인 캐릭터 위치에 재생한다. 방향은 `Parameters.Normal`을 현재 구면 Up의 접평면에 투영하고, 영벡터면 캐릭터 전방을 사용한다.
3. `FinishJustDodgeBlink`가 숨김을 복원할 때 현재 캐릭터 위치에서 나타남 시스템을 재생한다. 대시 방향을 타이머에 보존해 복원 위치의 접평면에 다시 투영한다. 오래된 서버 성공 위치로 몸을 옮기지 않는다. 이펙트는 숨긴 메시의 표시 상태를 따라 숨지 않게 한다.
4. 모든 이미터는 로컬 스페이스이며, 시스템은 각 버스트 위치에서 재생한다. 검은 전신 속도선과 흰색 중심선 모두 대시 축에 평행하게 흐르게 하고 힘 모듈을 끈다. 가시처럼 보인 방사형 수렴과 콘 퍼짐은 제거한다. 가운데의 가는 흰색 강조선도 크기·알파 커브로 완만하게 나타나고 사라진다. 원형 플래시와 캐릭터 오버레이는 쓰지 않는다(J-022).
5. 기존 성공 큐 에셋에 필요한 시스템 참조를 연결한다. 부모의 범용 VFX와 같은 버스트가 중복 재생되지 않게 한다. 기존 큐 도착 로그는 유지한다.

검증:

- Niagara·BP 컴파일과 저장 성공, 로컬 스페이스·수명·크기 커브 확인.
- 사용자 PIE에서 원점 약 24,000cm 밖의 실제 전투 위치에서도 픽셀이 그려지는지 확인한다(V-03).
- 모양·방향·밝기 조정은 사용자의 직접 재생·시각 평가가 더 빠르면 즉시 요청한다. 별도 자동 플레이 장치나 MCP 도구를 만들지 않는다.

완료 후 사용자에게 단위 3 진행 여부를 확인한다.

## 단위 3 — 2인 검증·수치 확정·인계

1. 리슨 2인에서 호스트 성공을 게스트가 관찰하고, 게스트 성공을 호스트가 관찰한다. 양쪽에서 숨김과 복원이 끝나고, 사라짐·나타남이 각 머신의 캐릭터 위치에 맞아야 한다(V-01의 V1a 범위).
2. 근접·직격 성공과 일반 대시를 묶어 사용자 플레이를 요청한다. 부재 0.12초와 나타남의 부드러움·전신 범위·검정/흰색 비율을 평가받는다. 잔상·오라·화면 효과가 없는 상태임을 구분한다.
3. [Validation.md §2](../design/Validation.md)의 공통 회귀를 확인한다. 전체 빌드 시 에디터를 닫고 `LootNPopEditor Win64 Development` 구성을 사용하며, 처음부터 권한 확장으로 실행한다. 커밋 뒤 깨끗한 트리 검증은 실제 커밋 여부에 맞춰 별도로 기록한다.
4. 지연 중 제자리 깜빡임 여부는 관찰해 남기되, 최종 판독과 J-007 재검토는 V4a가 소유한다. 이번 단위에서 예측 연출을 도입하지 않는다.
5. 승인된 수치를 `VisualDesign.md`에 반영한다. 색 방향은 J-021, 전신 범위와 플래시 선택은 J-022를 따른다. 실행서·로그·`Current.md`·`Roadmap.md`를 실제 결과로 갱신한다. V2 진행은 사용자 확인을 받는다.
