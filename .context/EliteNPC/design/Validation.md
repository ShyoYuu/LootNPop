# 엘리트 NPC 검증 규약

> 상태: 초안
> 소유: Phase별 검증 시나리오, 공통 회귀, 로그 판정 기준
> 마지막 갱신: 2026-11-05

## 1. 공통 준비

- 검증 편성은 별도 에셋(`DA_MassSpawnConfig_EliteTest` 등)으로 만들고 `LNP.Spawn.ConfigOverride` 또는 `-LNPSpawnConfig=`로 지정한다. 기본 `DA_MassSpawnConfig`는 검증용으로 바꾸지 않는다.
- 오버라이드는 호스트·게스트 모두에 준다(양쪽에서 템플릿을 등록한다).
- 같은 시드로 반복하려면 `OctantGenSeed`를 고정한다.
- 빌드: 프로젝트 공통 워크플로. 커밋 뒤 `-DisableAdaptiveUnity`로 한 번 더 확인한다.

## 2. 공통 회귀 (모든 Phase)

| 항목 | 확인 방법 | 통과 기준 |
|:---|:---|:---|
| Pod·Pod 적 배치 불변 | `LNPMassSpawnPlanTest`, 같은 시드 PIE의 스폰 로그 비교 | 엘리트 엔트리 유무와 무관하게 Pod·적 위치가 같다 |
| Pod 루팅·보상 | PIE에서 Pod 하나 루팅 | Popped 후 Dice 3~4개, Confetti |
| 기존 PureEntity 전투 | Pod 적과 교전 | 근접·원거리·경직·패링이 이전과 같다 |
| 빌드 | Build.bat | 깨끗한 트리에서 통과 |

## 3. Phase별 시나리오

### E1 스폰 구성·Roam 배치

- 데이터 검증: Pod 편성에 ActorPromoted를 넣으면 오류, Unbound에 Pod 모드·빈 ID·중복 ID를 넣으면 오류.
- 계획 테스트: Unbound Roam 2기 추가 전후의 Pod 계획 동일, 같은 시드 두 번 결과 동일, Roam 위치가 모든 Pod에서 `MinDistanceFromPods` 이상.
- PIE 로그: `[UnboundSpawn]` 줄 수 = 배치 수. 30초 동안 `[SurfaceNavHome]`에 엘리트 엔티티가 나오지 않는다(재귀속 없음).
- 임시 기간 확인: 엘리트가 `ST_EnemyEntity` IdleTask로 이상 동작(교착·낙하)을 하지 않는다.

### E2 사망 드랍

- 1P: Roam 엘리트 처치 → 사망 지점에 Dice가 `DeathRewards` 범위 수만큼.
- 2P: 게스트가 Dice를 보고 줍는다. 호스트 쪽에서 중복 스폰 없음(서버 로그 1회).
- Pod 보상 회귀: `SpawnRewardSet` 추출 후 Pod Popped 보상 수·후보가 같다.
- 보상이 빈 적(Pod PureEntity)은 드랍하지 않는다.

### E3 아레나 마커·베이크

- `LNPSpawnDataTest`: codec v4 왕복, 정렬·중복 ID 검증, 옛 v3 페이로드 Decode 실패.
- 재베이크 후 각 옥탄트 베이크 리포트에 아레나 앵커 수가 나온다.
- PIE: 아레나 엘리트가 마커 반경 안에 스폰된다. 태그가 없는 조합에서는 `[UnboundPlan] placed=0/N` 경고만 나고 진행된다.

### E4 Mass 매크로 두뇌

- Arena 피격 자격: 한 번도 교전하지 않은 보스를 밖에서 근접·직격·폭발로 공격 → HP·경직·넉백·피격 인지 변화 없음. 리셋 후 같은 공격을 반복해도 동일하다(EL-015).
- Arena 경계 탄: 안에서 발사하고 명중 전에 밖으로 나가면 피해 거부, 밖에서 발사하고 명중 전에 안으로 들어오면 위치 조건 통과. 안에 있는 동료의 교전이 밖 공격자의 자격을 대신하지 않는다. 스플래시는 폭발 중심과 공격자 위치를 각각 안/밖으로 바꿔 확인한다. 반사탄은 반사 후 공격자 귀속으로 검사한다.
- Arena 귀환: 안에서 교전 → 플레이어 전원 이탈 → Alert 타겟이 남아 있어도 HomeCenter로 실제 귀환. 도중 재진입해도 귀환을 유지하고 앵커 도착·지연 충족 후 리셋 1회, 이후 재교전(EL-016). 도착이 지연보다 빠른 경우와 늦은 경우를 각각 확인한다.
- Arena 귀환 중: 안에 있는 공격자도 피해·경직·넉백을 줄 수 없다. Return 목표를 TargetFollow가 덮지 않으며 Alert 정지 분기로 멈추지 않는다.
- Arena 넉백 귀환: 안에 유효한 플레이어를 남기고 보스를 밖으로 밀기 → 앵커 귀환까지 재교전 보류, HP 유지. 귀환 도중 플레이어가 전원 이탈하면 교전 해제 귀환으로 바뀌어 도착·지연 뒤 완전 리셋한다.
- Arena: 슬롯이 잠깐 끊겨도(2P에서 타겟 전환) 리셋되지 않는다.
- 리셋 재무장: 안의 허용된 피격만 받고 Confirmed가 되지 못한 경우도 지연 뒤 회복한다. 완전 리셋 후 다시 허용된 피격을 주면 새 리셋이 예약된다. 반복 피격이 타이머를 무한 연장하지 않는다.
- 리셋 정리: 그로기·다운 중 완전 리셋 → 경직 GA·차단 태그 해제, Config 유래 저항·임계값 보존, 엔티티/ASC HP 일치, 이후 이동·공격 정상. Actor 없는 리셋 뒤 승격해도 같은 상태다.
- 사망 우선: 허용된 치명타와 리셋 가능 시점이 겹친 프레임 → HP 부활 없음, 사망·드랍 1회. 반대로 밖 공격은 지연 안의 큰 피해여도 처치·드랍이 생기지 않는다. 실제 프로세서/커맨드 순서를 Phase 로그에 남긴다.
- Roam: 목적지 slot·Layer가 출발과 다른 경유점을 각각 지정해 도달한다. 5분 자연 배회에서 옥탄트 이음매 순회를 확인한다. 도달 불가·타임아웃·generation 변경 시 목표 폐기·재선정, 반복 요청 폭주 없음. Pod 기존 배회는 같은 표면 제약 유지.
- E4는 기존 Attack/Chase 폴백으로 확인한다. Engage의 두뇌 소유권과 새 패턴 정리는 E5에서 확인한다.

### E5 Actor 전투 두뇌 프레임워크

- 시험 엘리트(패턴 2개: 근거리·중거리)가 거리 대역에 따라 패턴을 고른다. StateTree 디버거로 상태 전이 확인.
- 패턴 중 경직 누적 → 패턴 어빌리티가 취소되고 Staggered 상태로 간다.
- 패턴 공격을 패링 → 패링 브레이크·넉백이 기존과 같다. 저스트 회피도 성립한다.
- 2P: 게스트 화면에서 패턴 몽타주가 재생된다.
- 전투 접근: Engage 전후 모두 벽·계단을 기존 경로로 우회한다. 측면 이동·후퇴의 도달 불가 후보는 실패로 종료하고 같은 목표를 무한 요청하지 않는다.
- 경계 이동: 일반 이동·측면 이동·루트 모션·Motion Warping이 아레나 경계를 넘지 않는다. 시작/종점은 안인데 중간 궤적이 밖인 패턴도 검사한다. 넉백 이탈은 귀환으로 처리한다.
- 패턴 수명: 원거리 패턴이 발사 순간 완료되지 않고 후딜까지 유지한다. 종료 이벤트는 해당 AbilitySpecHandle만 완료시키며, 발동 실패·발동 호출 안의 동기 종료도 대기 상태에 갇히지 않는다.
- 종료 경로: 패턴 중 Confirmed 상실·Return·리셋·사망·Actor EndPlay·두뇌 정지를 각각 실행한다. 다음 프레임의 새 공격/칼날 판정·워프·이전 이동 의도가 남지 않으며 두 번 정리해도 안전하다. 이미 비행 중인 발사체의 기존 수명과 새 발사 중단을 구분한다.
- 소유권 인계: 이전 Mass 이동 커맨드를 지연시킨 상태에서 Engage 시작/중지 → 뒤늦은 입력 덮어쓰기 없음. 경직 취소 콜백이 종료된 Task를 다시 완료시키지 않는다.
- 의도 소유권: Engage 중 MovementProcessor가 Actor 의도를 쓰지 않는다. Actor 강등 시 태그가 정리되고 Chase 폴백의 엔티티 이동이 이어진다.
- 페이즈 연출: 시작 전 발동 실패는 미소비, 시작 후 경직은 소비 유지. Phase2에서 경직·타겟 교체·재교전·Actor 재생성을 거쳐도 연출이 반복되지 않는다. Arena 완전 리셋 뒤에는 재허용하고 Roam Actor 재생성은 재허용하지 않는다(EL-017).
- E4 리셋 회귀를 패턴·연출 장부가 붙은 Actor로 다시 확인한다. 2P에서도 공격 취소·귀환·재교전의 모션이 맞는지 확인한 뒤 E6 콘텐츠를 늘린다.

### E6 첫 엘리트 콘텐츠·2P

- 아레나 보스: 2페이즈 전환 1회, 리셋 후 1페이즈 복귀, 처치 시 드랍.
- 배회형: 마주침 → 교전 → 놓침 → 배회 재개.
- 대역폭: [Guide_NetBandwidth.md](../../Guide_NetBandwidth.md) 절차로 Promoted Actor 1기당 B/s 측정. 700~900 B/s 범위를 넘으면 원인을 분리한다.
- 패키지 프레임: 에디터 `-game`이 아닌 패키지로 판정한다.
