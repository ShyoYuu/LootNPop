# Ridge U4-2 큰 배치 저작본 V002

사용자가 채택한 U4-1의 `LargeLayout_V001` JSON·맵·조립체는 그대로 보존한다. V002는 이전 맵을 복제하고 석교 남쪽 받침 절벽과 상류 입구의 독립 암괴만 추가하는 작업본이다.

- `RidgeLayout.json`: V037/V010 불변 기준, 채택된 V001 파일 해시·맵·소유자 자세/지문, 새 구역 JSON과 근거 폴더를 연결한다.
- `EDTerrainLayout_Z2.json`: 기존 하류 소유자와 새2개 소유자의 결과 자세·원본/사본 해시, 보호할 협곡·교량·Pod·동굴 접근·MesaAscent, 후속 몸체의 채움/빈 공간을 담는다.
- 기존 하류 소유자는 `previous_unit.locked_owners`로 고정한다. 새 맵에서 다른 자세/참조/결과 지문이 나오면 검사 실패다. V001의 승인 상태를 기록하려고 원본 JSON을 덮어쓰지 않는다.
- 새 `PL_LargeCliff_02e`·`01c` 사본은 원래 내부 배치와 크기를 유지한다. 원본·공유 메시/재질/BPP·기존 Cull 사본은 수정하지 않는다. 새 전용 층 살포·잔돌·식생 조정은 하지 않는다.

`RidgeLargeLayout.py export V002`는 V002 폴더의 manifest를 읽는다. 전체 dirty가 없고18개 하위 레벨이 로드된 상태에서 기존 Z1/채택 V001 보존·새 시각 NoCollision·표본 상자 검사를 한 뒤 실제 자세를 새 JSON에 되읽는다. 실패하면 JSON을 갱신하지 않는다. 검사 보고서는 `Saved/Profiling/Graphics/Phase01/U4_2_V002/`에 새 이름으로 남긴다.

상자 검사는 메시 로컬 상자에50cm 여유를 둔다. 협곡과 접근로는2m 간격3열, Pod는9m 원판의 중심/내·외곽, 교량은 원래 갑판 높이의 아래/위 표본을 사용한다. 시각 배치의 보수적 점검이며 실제 충돌·PIE·Nav 통과로 해석하지 않는다.

첫 검사에서 받침 절벽 뒤쪽이 MesaAscent와49건 겹쳐 새 받침만 위치/방향을 보정했다. 보호 폭은 유지하고 Pod 원판 위쪽도+1~61m의13층으로 추가 검사한다. 원본/채택 배치는 그대로다. 현재 자세와 근거는 구역 JSON 및 `U4_2_V002/Views_ClearanceCorrected/`를 따른다.

새 체크아웃에서 필요한 기존 에셋·새 조립체 사본을 준비한 뒤 `build V002`를 실행하면 채택된 V001 맵을 복제하고 고정되지 않은 새 소유자만 더한다. 동일 이름이 있으면 중단한다. Level Instance 로드 뒤 별도 Cmd에서 `verify V002`를 실행한다. 이미 있는 결과를 준비 목적으로 재실행하지 않는다.

몸체·충돌·SurfaceData·기반면 재빌드와 구조물 교체는 후속 단계다. 현재 마커/충돌은 V010의 보존 상태이며 새 시각 배치의 충돌을 설명하지 않는다.
